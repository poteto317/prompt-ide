# prompt-ide 実機テスト仕様書

アプリを `npm run dev` で起動し、実機で確認するためのチェックリスト。確認できた項目はタップしてチェックする。チェック付きで見るには、この仕様書から作った HTML ページ（Artifact）を開く（`node scripts/build-manual-test-spec.mjs` で再生成する）。
各項目は「手順 → 期待結果」の 1 行で書く。ID（例: EXP-001）はチェック状態の保存キーなので、振った ID は変更も再利用もしない。項目を追加するときは、領域ごとの最後の連番の次を使う。
機能を開発するたびに、この仕様書に項目を追記する（CLAUDE.md の共通ルール）。【要 API キー】【要 CLI】【要リモート】【要 Git リポジトリ】は、その環境が必要な項目。
各領域の先頭にある「前提」に、テスト用のフォルダやリポジトリの作り方がある。

- [ ] **BASE-004** `プロンプト` アイコンをクリックする → サイドバーの見出しが `プロンプト` に変わりプロンプト一覧が表示される

- [ ] **BASE-006** `実行履歴` アイコンをクリックする → サイドバーの見出しが `実行履歴` に変わり実行履歴の内容が表示される
- [ ] **BASE-007** `設定` アイコンをクリックする → サイドバーの見出しが `設定` に変わり `Anthropic API キー` と `モデル` の 2 つのセクションが表示される

- [ ] **BASE-011** サイドバーを閉じた状態で、同じアイコンをもう一度クリックする → サイドバーが再び開き、閉じる前と同じパネルが表示される
- [ ] **BASE-012** サイドバーを閉じた状態で、別のアイコン(例: `設定`)をクリックする → サイドバーが開き、クリックしたパネルの内容が表示される
- [ ] **BASE-013** サイドバーを閉じてから開き直す → 閉じる前にエクスプローラーで開いていたフォルダ・ファイルツリー・開いているタブ・エディタの内容は保持されたまま表示される

### エディタパネルとステータスバーのレイアウト

- [ ] **BASE-014** 起動直後の画面全体を見る → 左にアクティビティバー、その右にサイドバー、中央にエディタパネル、画面下端にステータスバーが並ぶ IDE 風のレイアウトになっている
- [ ] **BASE-015** 画面下端のステータスバーを見る → 左にブランチアイコンと `main`、右側に `TypeScript` `Ln 1, Col 1` `UTF-8` の表示がある(固定表示)
- [ ] **BASE-016** ウィンドウの大きさを小さく/大きく変える → サイドバー幅は一定のまま、エディタパネルが残りの領域に追随して伸縮し、ステータスバーは下端に残る

### クイックオープン

> 前提: フォルダを開き、複数のファイルを含むツリーが表示されている状態。下位フォルダ(例: `src/components/Button.tsx` のような階層)に同名でないファイルが複数あること。

- [ ] **BASE-018** エディタにフォーカスがある状態で Cmd(Windows/Linux は Ctrl)+P を押す → 画面中央にダイアログが現れる(見出しは無く、入力欄のプレースホルダ `ファイル名を入力` と候補一覧が見える)、入力欄にフォーカスが当たる
- [ ] **BASE-019** 一度もファイルを開いていない状態でクイックオープンを開く → フォルダ内のファイルが候補として一覧表示される
- [ ] **BASE-020** ファイルを 3 つ以上順に開いてからクイックオープンを開く(入力は空) → 最近開いたファイルが新しい順に表示され、現在開いているファイルは一覧に含まれない
- [ ] **BASE-021** 入力欄にファイル名の一部(例: `btn`)を入力する → 一致するファイルだけに絞り込まれ、一致した文字がハイライト表示される
- [ ] **BASE-022** 候補にサブフォルダ内のファイルがある状態で入力する → 候補にファイル名と、その親ディレクトリのパスが併記される
- [ ] **BASE-023** 候補が複数ある状態で `↓` キーを押す → 選択行(強調表示)が 1 つ下へ移り、最下行で `↓` を押すと先頭行に戻る
- [ ] **BASE-024** 候補が複数ある状態で先頭行から `↑` キーを押す → 選択行が最下行へ移る(ラップアラウンド)
- [ ] **BASE-025** 候補の行にマウスカーソルを移動する → カーソル位置の行が選択状態になる
- [ ] **BASE-026** 候補を選んで Enter を押す → ダイアログが閉じ、そのファイルがエディタのタブで開かれ、エディタにフォーカスが移る
- [ ] **BASE-027** 候補の行をクリックする → ダイアログが閉じ、そのファイルがエディタで開かれる
- [ ] **BASE-028** 存在しない文字列(例: `zzzzzz`)を入力する → 候補が空になり `一致するファイルがありません` と表示される
- [ ] **BASE-029** クイックオープンを開いた状態で Esc を押す → ダイアログが閉じ、開く前にフォーカスしていた要素にフォーカスが戻る
- [ ] **BASE-030** クイックオープンを開いた状態でダイアログの外側(暗い背景部分)をクリックする → ダイアログが閉じる
- [ ] **BASE-031** クイックオープンを開いた状態で Cmd(Windows/Linux は Ctrl)+P をもう一度押す → ダイアログは開いたまま、入力途中の文字は消えない
- [ ] **BASE-032** クイックオープンを開いて Tab キーを押す → フォーカスは入力欄から動かず、ダイアログの外へ移らない
- [ ] **BASE-033** フォルダを開いていない状態で Cmd(Windows/Linux は Ctrl)+P を押す → `フォルダが開かれていません。エクスプローラーからフォルダを開いてください` と表示される
- [ ] **BASE-034** 未保存の変更があるファイルを開いた状態で、別のファイルをクイックオープンで選んで Enter を押す → 別タブとして開かれ(破棄確認は出ない)、元のファイルのタブには未保存の `●` が残る
- [ ] **BASE-035** エクスプローラーでファイル名の変更ダイアログ(`リネーム: …`)を開いた状態で Cmd(Windows/Linux は Ctrl)+P を押す → クイックオープンは重ねて表示されない

### ダークテーマの見た目

- [ ] **BASE-036** 起動直後の画面全体を見る → 背景が暗色(濃いグレー系)で、サイドバー・エディタ・ステータスバーの文字が読みやすいコントラストで表示され、白く浮いた領域がない
- [ ] **BASE-037** エクスプローラー・設定・進捗管理の各パネルを順に開く → どのパネルも暗色の背景で、入力欄・ボタンの文字が背景に埋もれずに読める

## エクスプローラー

### フォルダを開く

> 前提: 数階層のサブフォルダと複数種類のファイル(`.ts` `.md` `.json` `.txt` など)を含むテスト用フォルダを用意しておく。`node_modules` `.git` を含むフォルダがあるとなお良い。

- [ ] **EXP-001** アプリ起動直後に `エクスプローラー` パネルを見る → `フォルダを開く` ボタンが表示され、ファイルツリーは表示されない
- [ ] **EXP-002** `フォルダを開く` をクリックする → OS のフォルダ選択ダイアログが開く
- [ ] **EXP-003** ダイアログでテスト用フォルダを選ぶ → ボタンが `フォルダを変更` に変わり、その下にファイルツリーが表示される
- [ ] **EXP-004** フォルダ選択ダイアログでキャンセルする → 表示は変わらず、エラーも表示されない
- [ ] **EXP-005** フォルダを開いた状態で `フォルダを変更` をクリックし、別のフォルダを選ぶ → ファイルツリーが新しいフォルダの内容に置き換わる
- [ ] **EXP-006** ファイルを開いて未保存の変更がある状態で `フォルダを変更` から別のフォルダを選ぶ → `保存されていない変更があります。破棄して続行しますか？` の確認ダイアログが出る
- [ ] **EXP-007** 上の確認ダイアログでキャンセルする → フォルダは変わらず、未保存のタブと編集内容がそのまま残る
- [ ] **EXP-008** 上の確認ダイアログで OK を選び、フォルダ選択ダイアログで別のフォルダを選ぶ → ツリーが新しいフォルダに切り替わり、これまで開いていたタブがすべて閉じて Welcome 表示になる

### ファイルツリーの表示

- [ ] **EXP-009** フォルダを開いた直後のツリーを見る → ディレクトリが先に、ファイルが後に並び、それぞれ名前順で表示される
- [ ] **EXP-010** ディレクトリの行を見る → 行頭に `▾`(展開中)が付き、初期状態ではサブディレクトリの中身が展開されて見えている
- [ ] **EXP-011** ディレクトリの行をクリックする → 行頭が `▸` に変わり、配下の項目が非表示になる
- [ ] **EXP-012** 折りたたんだディレクトリをもう一度クリックする → `▾` に戻り、配下の項目が再び表示される
- [ ] **EXP-013** ディレクトリの行を Tab キーで選び Enter(または Space)を押す → クリックと同じように展開/折りたたみが切り替わる
- [ ] **EXP-014** 階層の深い項目を見る → 階層が深いほど左の余白(インデント)が大きく、親子関係が分かる
- [ ] **EXP-015** `node_modules` `.git` `out` `dist` `.next` というフォルダを含むフォルダを開く → これらのフォルダはツリーに表示されない
- [ ] **EXP-016** ルートから 7 階層以上の深さにフォルダ・ファイルを置いたフォルダを開く → ルート直下を 1 階層目として 6 階層目までが表示され、7 階層目以降の項目は表示されない(6 階層目のフォルダは中身が空で表示される)
- [ ] **EXP-017** 読み取り権限のないサブフォルダ(`chmod 000 sub` したもの)を含むフォルダを開く → アプリは落ちず、ツリーは空のままで、エクスプローラー上部に `EACCES: permission denied, scandir` を含む赤字のエラーが表示される(フォルダ全体の読み込みが失敗する。権限のないファイルだけなら通常どおりツリーに並ぶ)

### ファイルを開く

- [ ] **EXP-018** ツリーのファイルをクリックする → 右のエディタにファイルの内容が表示され、タブにファイル名が出る
- [ ] **EXP-019** ファイルを開いた状態でツリーの該当行を見る → その行が選択状態(強調表示)になる
- [ ] **EXP-020** ツリーのファイルを Tab キーで選び Enter(または Space)を押す → クリックと同じくファイルが開く
- [ ] **EXP-021** すでにタブで開いているファイルをもう一度クリックする → 新しいタブは増えず、既存のタブがアクティブになる
- [ ] **EXP-022** 別のファイルをクリックする → 新しいタブが追加されてアクティブになり、前のファイルのタブも残る
- [ ] **EXP-023** 未保存の変更があるファイルを開いた状態で、別のファイルをクリックする → 破棄確認は出ず、別タブとして開き、元のタブには `●` が残る
- [ ] **EXP-024** 空ファイル(0 バイト)をクリックする → エラーにならず、空のエディタが表示される

### コンテキストメニュー

- [ ] **EXP-026** ファイルの行を右クリックする → メニューに `リネーム` `削除` `.gitignore に追加` が表示され、`新規ファイル` `新規フォルダ` は出ない
- [ ] **EXP-027** ファイルツリーの項目がない余白部分を右クリックする → メニューに `新規ファイル` `新規フォルダ` だけが表示される
- [ ] **EXP-028** メニューを表示した状態でメニューの外をクリックする → メニューが閉じる
- [ ] **EXP-029** メニューを表示した状態で Esc を押す → メニューが閉じる
- [ ] **EXP-030** メニューを表示した状態で別の項目を右クリックする → 前のメニューが閉じ、新しい位置にメニューが表示される
- [ ] **EXP-031** フォルダを開いていない状態でエクスプローラーを右クリックする → メニューは表示されない

### 新規ファイル・新規フォルダの作成

- [ ] **EXP-032** ディレクトリを右クリックして `新規ファイル` を選ぶ → `新規ファイル` というタイトルのダイアログが開き、名前入力欄にフォーカスが当たる(`OK` と `キャンセル` ボタンがある)
- [ ] **EXP-033** 上のダイアログに `new-file.txt` と入力して `OK` を押す → ダイアログが閉じ、そのディレクトリ直下に `new-file.txt` がツリーに現れる
- [ ] **EXP-034** 余白を右クリックして `新規フォルダ` を選び、`new-dir` と入力して `OK` を押す → ルート直下に `new-dir` フォルダがツリーに現れる
- [ ] **EXP-035** 新規作成したファイルを実際にディスク上で確認する → 空のファイルが作成されている(0 バイト)
- [ ] **EXP-036** ファイルを作成した直後のエディタを見る → 作成したファイルは自動では開かれない(クリックして初めて開く)
- [ ] **EXP-037** 名前入力欄で Enter を押す → `OK` を押したときと同じく作成される
- [ ] **EXP-038** 名前入力欄で Esc を押す → ダイアログが閉じ、何も作成されない
- [ ] **EXP-039** `キャンセル` ボタンを押す → ダイアログが閉じ、何も作成されない
- [ ] **EXP-040** ダイアログの外側(暗い背景)をクリックする → ダイアログが閉じ、何も作成されない
- [ ] **EXP-041** 既に同じ名前のファイルがあるディレクトリで同じ名前を入力して `OK` を押す → ダイアログは閉じ、エクスプローラー上部に `既に存在します: <名前>` を含む赤字が表示され、既存ファイルは変更されない
- [ ] **EXP-042** 前後に空白を付けた名前(例: `spaced.txt`)を入力して `OK` を押す → 前後の空白が取り除かれた `spaced.txt` が作成される

### リネーム

- [ ] **EXP-052** ファイルを右クリックして `リネーム` を選ぶ → タイトルが `リネーム: <現在の名前>` のダイアログが開き、入力欄に現在の名前が入っている
- [ ] **EXP-053** 新しい名前を入力して `OK` を押す → ツリー上のファイル名が新しい名前に変わる
- [ ] **EXP-054** ディレクトリを右クリックして `リネーム` から名前を変える → ツリー上のディレクトリ名が変わり、配下の項目も保持される

## ソース管理（基本）

## ブランチ操作

> 前提: リモート無しのテスト用リポジトリを作り、アプリで「フォルダを開く」から開く。`mkdir /tmp/brn-test && cd /tmp/brn-test && git init -b main && git config user.name t && git config user.email t@example.com && printf 'line1\nline2\nline3\n' > a.txt && printf 'base\n' > b.txt && git add . && git commit -m init`
> 前提(ブランチ): 早送り用 `git branch ff-branch && git checkout ff-branch && echo ff > ff.txt && git add ff.txt && git commit -m ff-commit && git checkout main`。マージコミット用 `git checkout -b merge-branch main && echo m > m.txt && git add m.txt && git commit -m m-commit && git checkout main && echo main-side > main-side.txt && git add main-side.txt && git commit -m main-commit`。未マージ削除用 `git checkout -b unmerged main && echo u > u.txt && git add u.txt && git commit -m u-commit && git checkout main`。
> 前提(コンフリクト): `git checkout -b conflict-a main && printf 'A\nline2\nline3\n' > a.txt && git commit -am conflict-a && git checkout -b conflict-b main && printf 'B\nline2\nline3\n' > a.txt && git commit -am conflict-b && git checkout conflict-a`。conflict-a 上で conflict-b をマージすると a.txt の 1 行目が衝突する。
> 前提: 確認ダイアログは OS ネイティブの確認(OK / キャンセル)。ソース管理パネル(サイドバーのソース管理)上部のブランチ名ボタンがブランチスイッチャー。

## 退避（stash）

> 前提: リモート無しのテスト用リポジトリを作り、アプリで開く。`mkdir /tmp/sth-test && cd /tmp/sth-test && git init -b main && git config user.name t && git config user.email t@example.com && printf 'one\ntwo\nthree\n' > a.txt && printf 'base\n' > b.txt && git add . && git commit -m init`
> 前提(各種の変更を用意): 未ステージ `echo changed >> a.txt`、ステージ済み `echo staged >> b.txt && git add b.txt`、未追跡 `echo new > new.txt`。この 3 種が「変更」「ステージ済み」に出ていれば退避の対象が揃っている。
> 前提(コンフリクトで戻せない状況): `echo stash-side > a.txt` してアプリで「退避する」→ 退避後にターミナルで `echo main-side > a.txt && git commit -am main-change` を実行(作業ツリーはきれい)。この状態で退避を戻すと a.txt が衝突する。
> 前提: 「退避」セクションは「変更」セクションの下、履歴の上にある。見出しは `退避（件数）`。確認ダイアログは OS ネイティブの確認(OK / キャンセル)。

## 変更の取り消しの拡張

> 前提: リモート無しのテスト用リポジトリを作り、アプリで開く。複数のハンクが出るよう行数の多いファイルを使う。`mkdir /tmp/dsc-test && cd /tmp/dsc-test && git init -b main && git config user.name t && git config user.email t@example.com && seq 1 60 > f.txt && echo base > g.txt && echo keep > h.txt && git add . && git commit -m init`
> 前提(複数ハンク): `sed -i.bak -e '2s/.*/CHANGED-2/' -e '58s/.*/CHANGED-58/' f.txt && rm f.txt.bak`(macOS の sed は `-i.bak` が必要)。f.txt の diff に離れた 2 つのハンク(2 行目付近と 58 行目付近)が出る。

## マージコンフリクトの解決

> 前提: コンフリクトのあるテスト用リポジトリを作る。`cd "$(mktemp -d)" && git init -b main && git config user.name t && git config user.email t@example.com && seq 1 20 > a.txt && printf 'Title\n=======\nbody\n' > doc.md && echo base > del.txt && git add . && git commit -m init`
> 前提(feat 側): `git checkout -b feat && sed -i.bak -e '3s/.*/FEAT-3/' -e '15s/.*/FEAT-15/' a.txt && sed -i.bak '3s/.*/feat body/' doc.md && rm a.txt.bak doc.md.bak && echo feat > del.txt && printf 'feat\0bin' > bin.dat && git add . && git commit -m feat`(macOS の sed は `-i.bak` が必要)。
> 前提(main 側): `git checkout main && sed -i.bak -e '3s/.*/MAIN-3/' -e '15s/.*/MAIN-15/' a.txt && sed -i.bak '3s/.*/main body/' doc.md && rm a.txt.bak doc.md.bak && git rm -q del.txt && printf 'main\0bin' > bin.dat && git add . && git commit -m main-side`。`a.txt` は 3 行目と 15 行目が別内容(ブロック 2 つ)、`doc.md` は 3 行目が別内容で 2 行目に見出し下線 `=======` を含み、`del.txt` は `main` で削除・`feat` で変更(追加/削除型)、`bin.dat` は両方で別内容のバイナリになる。
> 前提: アプリでこのフォルダを開き、ソース管理パネルのブランチ名ボタンのメニューで `feat` 行の `🔀` を押し、マージの確認で「OK」を押す。確認ダイアログは OS ネイティブの確認(OK / キャンセル)。未解決のファイルは「変更」セクションに並び、ファイル名をタップすると解決ビューが開く。各項目で状態をやり直すときは、コンフリクトを作る手順からもう一度行う。

### サブモジュールのコンフリクト

> 前提: 端末で `mktemp -d` の中に、空コミットを 3 つ(共通祖先・自分・相手。相手は共通祖先から分岐)持つリポジトリ `subsrc` と、本体のリポジトリ `repo` を作る。`repo` で `git -c protocol.file.allow=always submodule add ../subsrc sub` し、`sub` を共通祖先のコミットにしてコミットする。`feat` ブランチでは `sub` を相手のコミットに、`main` では自分のコミットに切り替えてそれぞれコミットし、`main` で `git merge feat` を実行して `sub` を `UU` にする。アプリで `repo` を開く。

- [ ] **CNF-060** CNF-059 のあと、端末で `cd sub && git checkout <相手のコミット> && cd .. && git add sub` を実行し、パネルの `更新` を押す → `sub` が未解決の一覧から消え、バナーが `マージ中（すべて解決済み。マージを完了できます）` になる。`マージを完了` を押すと、マージコミットの `sub` が相手のコミットを指している(`git ls-tree HEAD sub`)

- [ ] **PRG-001** 進捗管理パネルを開く(タスクが 0 件) → `タスクがありません` が表示され、下部に `タスク名` 入力欄と `タスクを追加` ボタンがある
- [ ] **PRG-002** 入力欄が空の状態で `タスクを追加` ボタンを見る → 無効状態になっている
- [ ] **PRG-003** 空白だけを入力する → `タスクを追加` ボタンは無効のまま
- [ ] **PRG-004** `機能A` と入力して `タスクを追加` を押す → タスクが追加され、タスク名 `機能A` と `進捗 0/8` が表示され、入力欄が空になる
- [ ] **PRG-005** 入力欄で Enter を押す → `タスクを追加` を押したときと同じくタスクが追加される
- [ ] **PRG-006** 前後に空白を付けた名前(`機能B`)で追加する → 前後の空白を除いたタスク名で表示される
- [ ] **PRG-007** タスクを 1 つだけ持つ状態でパネル上部を見る → タスク選択のドロップダウンは表示されない
- [ ] **PRG-008** 2 つ目のタスクを追加する → パネル上部にタスク選択のドロップダウン(`タスクを選択`)が現れ、2 つのタスク名が選べる
- [ ] **PRG-009** ドロップダウンで別のタスクを選ぶ → 表示されるタスク名・ステージの状態が選んだタスクのものに切り替わる

### ステージの初期表示

- [ ] **PRG-010** 追加直後のタスクのステージ一覧を見る → `1. プラン作成` `2. 機能の実装` `3. 単一責任にリファクタリング` `4. ローカルレビュー` `5. コミット` `6. PR 作成` `7. PR コードレビュー` `8. PR マージ` の 8 行が順に並ぶ
- [ ] **PRG-011** 追加直後の各ステージのアイコンを見る → すべて `○`(未着手)で、進捗は `進捗 0/8`
- [ ] **PRG-012** 追加直後の現在ステージを見る → `1. プラン作成` が現在のステージとして強調表示される
- [ ] **PRG-013** `6. PR 作成` と `8. PR マージ` の行を見る → 名前の横に `(一度きり)` が表示される
- [ ] **PRG-014** 一覧の下の凡例を見る → `● 完了` `◐ 進行中` `○ 未着手` `⊘ スキップ` が順に表示される
- [ ] **PRG-015** ステージのアイコンにカーソルを合わせる → `未着手` などの状態名がツールチップで表示される

### ステージの進行(次へ進む)

- [ ] **PRG-016** 追加直後の `1. プラン作成` の行のボタンを見る → `スキップ` と `次へ進む` が表示される
- [ ] **PRG-017** `1. プラン作成` の `次へ進む` を押す → `1. プラン作成` が `●`(完了)、`2. 機能の実装` が `◐`(進行中)になり、現在のステージが `2. 機能の実装` に移る。進捗は `進捗 1/8`
- [ ] **PRG-018** `次へ進む` を繰り返し押して現在ステージを進める → 完了したステージが `●`、次のステージが `◐` になり、進捗の分子が増える
- [ ] **PRG-019** 現在ステージでないステージの行を見る → `次へ進む` ボタンは現在ステージの行にだけ表示される
- [ ] **PRG-020** 現在ステージが `8. PR マージ`(最終ステージ)のとき → `次へ進む` は表示されない

### スキップ

- [ ] **PRG-021** 未着手または進行中のステージの `スキップ` を押す → そのステージのアイコンが `⊘`(スキップ)になり、`スキップ` ボタンが消える
- [ ] **PRG-022** 現在ステージをスキップしてから `次へ進む` を押す → スキップしたステージは `⊘` のまま(完了にならず)、次のステージが `◐` になる
- [ ] **PRG-023** スキップしたステージを含めて進捗を見る → スキップしたステージは完了数に数えられない(`進捗 n/8` の n に含まれない)
- [ ] **PRG-024** 完了済み(`●`)のステージの行を見る → `スキップ` ボタンは表示されない

### 一度きりのステージ(完了にする・未完了に戻す)

- [ ] **PRG-025** `6. PR 作成` の行を見る → `完了にする` と `スキップ` ボタンが表示される
- [ ] **PRG-026** `6. PR 作成` の `完了にする` を押す → アイコンが `●` になり、ボタンが `未完了に戻す` に変わる。進捗が 1 増える
- [ ] **PRG-027** `6. PR 作成` の `未完了に戻す` を押す → アイコンが未完了の状態(○ または ◐)に戻り、`完了にする` が再び表示される
- [ ] **PRG-028** `8. PR マージ` が現在ステージのとき `完了にする` を押す → 完了になり進捗が増える

### 再開(再オープン)

- [ ] **PRG-029** 完了済みの `2. 機能の実装` の行を見る → `再開する` ボタンが表示される
- [ ] **PRG-030** 実施記録のない完了済みステージの `再開する` を押す → そのステージが `○`(未着手)に戻り、現在ステージがそのステージに移る
- [ ] **PRG-031** 実施記録のある完了済みステージの `再開する` を押す → そのステージが `◐`(進行中)に戻り、現在ステージがそのステージに移る
- [ ] **PRG-032** 後続ステージが完了済みの状態で、前のステージを `再開する` → 後続の完了済みステージが `◐`(進行中)に落ちる

### 履歴の表示と実施の記録

- [ ] **PRG-033** `1. プラン作成` の行の右端の `v` ボタンを押す → 履歴の領域が開き、ボタンが `∧` に変わる
- [ ] **PRG-034** 実施記録がないステージの履歴を開く → `履歴はありません` が表示される
- [ ] **PRG-035** 開いた履歴をもう一度 `∧` で閉じる → 履歴の領域が閉じる
- [ ] **PRG-036** 繰り返し可能/改訂可能なステージ(プラン作成・実装・リファクタなど)の履歴を開く → `メモ（任意）` 入力欄と `実施を記録する` ボタンが表示される
- [ ] **PRG-037** `6. PR 作成` や `8. PR マージ`(一度きり)の履歴を開く → 履歴の一覧だけが表示され、`実施を記録する` の入力欄は表示されない
- [ ] **PRG-038** メモ欄を空のまま `実施を記録する` を押す → 履歴に日時(`YYYY/MM/DD HH:mm` 形式)だけの記録が 1 件追加される
- [ ] **PRG-039** メモ欄に `レビュー指摘を反映` と入力して `実施を記録する` を押す → 履歴に日時とメモ `レビュー指摘を反映` が追加され、メモ欄が空になる
- [ ] **PRG-040** 未着手のステージで実施を記録する → ステージが `◐`(進行中)になる
- [ ] **PRG-041** 実施を複数回記録する → ステージの名前の横に `×2` `×3` のような実施回数のバッジが増えていく
- [ ] **PRG-042** 完了済みのステージで実施を記録する → ステージは `●`(完了)のまま、履歴が追加される
- [ ] **PRG-043** 履歴を持つステージの履歴を閉じてから開き直す → 記録した履歴がそのまま表示される

### タスクの削除と永続化

- [ ] **PRG-044** タスクのヘッダーにある `削除` ボタンを押す → 確認なしでそのタスクが一覧から消える
- [ ] **PRG-045** 複数タスクのうち選択中のタスクを削除する → 残りのタスクのどれかが表示される
- [ ] **PRG-046** すべてのタスクを削除する → `タスクがありません` の表示に戻る
- [ ] **PRG-047** タスクを追加し、ステージを進めて履歴を記録したあと、アプリを終了して再起動する → タスク・ステージの状態・履歴・実施回数がそのまま復元される
- [ ] **PRG-048** 進捗管理パネルを別のパネルに切り替えて戻る → 選択中のタスクとステージの状態が保持されている
- [ ] **PRG-049** 進捗管理パネル全体を見る → 暗色の背景で、現在ステージの強調やステータスアイコンが識別しやすい
