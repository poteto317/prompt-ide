## 目的

エージェントの変更のセクション（ソース管理パネル）は、記録を利用者のリポジトリの object の DB と、アプリの一時ディレクトリに置いた記録のインデックス（`GIT_INDEX_FILE`）で作る。そのため Git 管理外のフォルダでは `takeBaselineSnapshot` が `not-repository` を返し（`agentBaselineSnapshot.ts:294-297`）、記録・一覧・diff・戻す・実行ごとの表示・利用者の変更との区別・取り消しのどれも使えない。セクションは `Git 管理外のフォルダでは、エージェントの変更を記録できません` だけを出す（`AgentChangesSection.tsx:146-150`・`agentChangesMessages.ts:96`）。

この機能では、Git 管理外のフォルダを開いたときに、アプリの一時ディレクトリの中に記録専用の bare リポジトリ（以下「隠れた git」）を作り、`GIT_DIR`・`GIT_WORK_TREE`・`GIT_INDEX_FILE` で開いたフォルダを作業ツリーとして記録する。利用者のフォルダには何も書かない（`.git` を作らない）。記録の後は、リポジトリと同じセクション・同じ操作（一覧・diff・戻す・すべて戻す・実行ごと・区別・取り消し）が使える。

## 範囲

含めるもの:

- 記録の git の場所の型（`BaselineGitLocation`）と、`GIT_DIR`・`GIT_WORK_TREE` を明示的に渡す環境（`buildBaselineGitEnv`）。記録の git を作る関数（`createBaselineGit`・`runBaselineGitWithInput`・`runBaselineGitWithInputSync`）を場所で受ける形にし、呼び出し元（記録・一覧・diff・戻す・保護の ref）を直す
- 隠れた git の作成（新しいファイル `agentBaselineHiddenGit.ts`）と、記録に含めない既定の一覧
- `takeBaselineSnapshot` の方式の決め方（リポジトリ・隠れた git の新規・隠れた git の区切り・`inside-git-dir`）と、隠れた git の記録の手順。区切りの写しの元を `base`（記録のインデックスと隠れた git の場所）で渡す
- 一覧・diff・戻すの、HEAD・コンフリクト・blob の問い合わせ先の切り替え
- 保護の同期を隠れた git の記録で何もしない
- 記録の一時ディレクトリの名前に `instanceId` を入れることと、起動時の掃除（新しいファイル `agentBaselineTempSweep.ts`）
- IPC の型（`storage`・理由 `too-many-files`・`inside-git-dir`）と renderer（セクションの注記・Git 管理外の表示の分岐の撤去・文言）
- ROADMAP（項目を実装済みへ・既知の制約）・2026-10-06 の設計書への注記・実機テスト仕様書（AGC-005・GIT-006 の修正と新しい項目）

含めないもの（頼まれていない。ROADMAP に残す・残す必要が無い）:

- リポジトリのサブフォルダ（`not-toplevel`）での記録
- 記録に含めないものの設定の画面
- 取り消しの控えの一時ディレクトリの起動時の掃除
- 開いたフォルダのファイルシステムの性質（大文字小文字の区別・シンボリックリンク）の判定
- 記録中に方式を変えること（`git init` の後にリポジトリの方式へ移す・`.git` を消した後に隠れた git へ移す）

## 確認の結果（設計時に確かめた事実。2026-10-15）

手元の git は `git version 2.50.1 (Apple Git-155)`。スクラッチパッドの中に Git 管理外のフォルダと一時ディレクトリを作り、端末で確かめた。1〜11 は git の実測、12 は simple-git の実測、13 はコードの読み取り。

1. **隠れた git の作成**: `git init --bare -q --template= <一時>/git`（環境から `GIT_DIR`・`GIT_WORK_TREE`・`GIT_INDEX_FILE` を外し、cwd は一時ディレクトリ）は `HEAD`・`config`・`objects`・`refs` だけを作る（`hooks`・`info`・`description` を作らない）。`-c init.templateDir=<hook のあるテンプレート>` を付けても `--template=` が勝ち、`hooks` を作らない（付けないと作る）。`config` は `bare = true`・`filemode = true`・`ignorecase = true`・`precomposeunicode = true`（macOS の一時ディレクトリで git が調べた値）
2. **未追跡の検査**: `GIT_DIR=<一時>/git`・`GIT_WORK_TREE=<フォルダ>`・`GIT_INDEX_FILE=<存在しないファイル>` で `ls-files -z --others --exclude-standard` を実行すると、フォルダの ignore されていないファイルがすべて出る。フォルダの `.gitignore`（`.env`）と隠れた git の `info/exclude`（`node_modules/`・`.venv/`）の両方に従う。存在しない index のファイルは作られない（`-c core.untrackedCache=true -c feature.manyFiles=true` を付けても作られない）
3. **記録**: 同じ環境で `GIT_INDEX_FILE` を一時ディレクトリの `index` にして `add -A .` すると、`100644`（通常）・`100755`（実行ビット）・`120000`（シンボリックリンク。リンクの指す先の文字列を記録し、指す先〈フォルダの外の `../outside.txt`〉を辿らない）・バイナリが記録される。`write-tree` は tree の ID を返す。`rev-parse --verify -q HEAD` は出力が空で終了コード 1
4. **一覧・戻す**: `diff --name-status --no-renames -z`（`M a.txt`・`D src/b.js`）・`ls-files --others --exclude-standard --directory --no-empty-directory`（`c.txt`）・`restore --worktree -- a.txt src/b.js`（元の内容に戻る）・`cat-file -t <blob>`（`blob`）・`ls-files -u`（空）・`check-attr -z filter`（`unspecified`）が動く。シンボリックリンクを別の指す先に作り直すと `M` になり、`restore --worktree` で元の指す先（`../outside.txt`）のリンクに戻る。一連の操作の前後で、フォルダの中のパスの一覧（`find . | sort`）は、操作で足した・消したもの以外は変わらない（`.git` などは作られない）
5. **記録中に利用者が `git init`**: フォルダで `git init` した後も、隠れた git の `ls-files --others`（`--exclude-standard` の有無に関わらず）にフォルダの `.git/` は出ず、`add -A .` は `.git` の中を記録しない（`ls-files` に `.git/` で始まる行が 0 件）。壊れた `.git` のファイル（`gitdir: /nonexistent`）も同じく出ない・記録しない。利用者の側（`GIT_DIR` などを付けない）の `git status` は、隠れた git と関係なく全ファイルを未追跡として出す
6. **入れ子のリポジトリ**: フォルダの中のリポジトリは `ls-files --others` に `sub1/`・`sub2/` の 1 行で出る。コミットのあるものは `add -A` で gitlink（`160000`）として記録され、`warning: adding embedded git repository` が出る（今の `advice.addEmbeddedRepo=false` で消せる）。コミットの無いもの（`sub2`）は今と同じく `:(exclude,literal)sub2` で外せる（今の `skippedRepos` の扱いがそのまま当てはまる）
7. **保護の ref**: 隠れた git でも `update-ref -z --stdin` と `for-each-ref` は動く（保護の ref を作れること自体は確かめた。作らない理由は「決めたこと（推奨案）」）
8. **`.git` の中・bare リポジトリ**: bare リポジトリのフォルダと `.git` の中では `rev-parse --is-inside-work-tree` が `false` を出し（`checkIsRepo` は偽）、`rev-parse --git-dir` は成功する（`.` を出す）。Git 管理外のフォルダでは `rev-parse --git-dir` が `fatal: not a git repository` で終了コード 128
9. **bare の守り**: 隠れた git に `GIT_WORK_TREE` を渡さずに `add -A .` すると、`fatal: this operation must be run in a work tree` で失敗し、何も書かない。`GIT_WORK_TREE` を渡せば `core.bare = true` のままでも `status`・`add`・`restore` が動く
10. **ハンクを戻す**: Git 管理外のフォルダで、隠れた git の `diff` で作ったパッチに `git apply --reverse --check -`・`git apply --numstat -z --reverse -`・`git apply --reverse -` が動き、パスは cwd（フォルダ）からの相対で解釈される（今の `discardHunkPatch`・`verifyHunkPatch` がそのまま使える）。フォルダに何も作らない

    > 2026-10-15 のローカルレビュー第 6 周の後の変更: 逆適用（`git apply --reverse -`）は、そのまま動かすと git がリポジトリの外として利用者の大域・システムの設定だけを読み、大域の `core.autocrlf=true` でファイル全体を CRLF で書き戻す。隠れた git の記録では、同じ `discardHunkPatch` を記録の git の環境（`GIT_DIR`・`GIT_WORK_TREE`）と `-c` の守り（`baselineGitSpawnEnvironment`）を渡して動かす（「部品の変更」の戻す）。

    > 2026-10-18 のローカルレビュー第 9 周の後の変更: 第 6 周では逆適用を `runBaselineGitWithInput` で動かしていたため、隠れた git の場合だけ打ち切りが記録の git の 10 秒で、すぐ SIGKILL していた（リポジトリの方式は `runGitApply` の 30 秒で SIGTERM、5 秒の猶予の後に SIGKILL）。`git apply` は古いファイルを消してから新しいファイルを作るため、途中で SIGKILL するとファイルが無いまま残りうる。`runGitApply`・`discardHunkPatch` が環境（`GitApplyEnvironment`。env と `-c`）を受け取れるようにし、どちらの方式も同じ実行の関数・同じ打ち切りの規則で動かす（`gitOptions` の `timeoutMs` は使わない）。パッチの検査（`verifyHunkPatch` の `--numstat`。順・逆）はファイルを書かないため、今の部品のまま

11. **既定の一覧の打ち消し**: `info/exclude` の `build/`・`dist/` で除いたフォルダは、フォルダの `.gitignore` に `!build/` を書くと記録の対象に戻る（`.gitignore` は `info/exclude` より優先される）。設定の画面が無くても、利用者が `.gitignore` で既定の一覧を打ち消せる
12. **時間と大きさ**: 50 のフォルダに 100 件ずつ（5,000 件）の小さなファイルを置いたフォルダで、隠れた git の作成・未追跡の検査・`add -A`・`write-tree` は合わせて 1.7 秒、隠れた git の大きさは 20MB（ファイルごとの loose object のため、1 件につき 4KB のブロックを使う）。1 件を変えて写しの元の index から `add -A` し直すと 0.02 秒
13. **simple-git の環境**: simple-git（このリポジトリの依存）の `env()` に `GIT_DIR`・`GIT_WORK_TREE`・`GIT_INDEX_FILE` を渡して `raw(['ls-files', ...])` を呼ぶと、拒否されずに隠れた git で動く（`SIMPLE_GIT_BLOCKED_ENV_KEYS` の 18 個に含まれない）
14. **既存のコード**: 記録の git を作る箇所は `createBaselineGit`（`agentBaselineGit.ts:87-101`）・`runBaselineGitWithInput`（:123）・`runBaselineGitWithInputSync`（:183）と、利用者の index で問い合わせる `createRepoGit`（:105-110）。`createRepoGit` の呼び出しは `agentBaselineSnapshot.ts:242`（入れ子のリポジトリの HEAD。今のまま）・:288（最上位の確認・利用者の index の場所・未追跡の検査・利用者の追跡済みの一覧・HEAD）・`agentChangesQuery.ts:219`（一覧の HEAD）・`agentChangesRevert.ts:148`（コンフリクトの判定と blob の有無）の 4 か所。`buildBaselineGitEnv`（`agentBaselineGit.ts:55-74`）は `GIT_DIR`・`GIT_WORK_TREE` などの位置の変数（`REPO_LOCATION_ENV_KEYS`。:39-47）を意図的に外し、`GIT_INDEX_FILE` だけを足す。区切りの写しの元は `latestRecordedIndexPath`（`agentChangesRecord.ts:170-176`）を registry が `baseIndexPath` で渡す（`agentBaselineRegistry.ts:553-557` の実行の区切りと、:814-819 の判定の区切り）。記録の一時ディレクトリの接頭辞は `prompt-ide-agent-baseline-`（`agentBaselineSnapshot.ts:82`）で pid を含まず、異常終了で残ったものは OS の掃除に任せている（`agentBaselineLifecycle.ts` のコメント）。renderer は `NotRepositoryView` の下にセクションを `isNotRepository` 付きで出し（`NotRepositoryView.tsx:64`）、記録の前は理由の 1 行だけを出す（`AgentChangesSection.tsx:146-150`）。管理外で記録できなかった後に初期化したときの特例（:79-82）がある

## 記録の方式（main）

### 方式の決め方（`agentBaselineMode.ts` の `resolveBaselineMode`）

`takeBaselineSnapshot(folderPath, options)` の `options.base`（区切りの写しの元。下の「区切りの写しの元」）で決める。

1. `base` があり `base.gitDir` が null（リポジトリの方式の記録の区切り）: 今の手順のまま。`checkIsRepo` が偽なら `not-repository`、最上位でなければ `not-toplevel`
2. `base` があり `base.gitDir` が文字列（隠れた git の記録の区切り）: フォルダを調べ直さず、隠れた git の方式にする。`base.gitDir` を `lstat` し、シンボリックリンクでないディレクトリでなければ例外（`git-failed`。新しい隠れた git を作らない。L-002）
3. `base` が無い（累積の始点）: `checkIsRepo` が真なら、最上位の確認を経てリポジトリの方式（今のまま）。偽なら `rev-parse --git-dir` を試し（`isInsideGitDirectory` を `gitRemoteSetupService.ts` から共通の場所へ移して使う）、成功すれば `inside-git-dir`、打ち切りなら `timeout`、それ以外の失敗なら隠れた git の新規

方式の判定の git（`checkIsRepo`・`rev-parse --show-toplevel`・`rev-parse --git-dir`）は `agentBaselineGit.ts` の `createModeGit` で作る（ローカルレビュー第 2 周の指摘 1 で追加）。simple-git の `checkIsRepo` は「リポジトリでない」を git の英語（とドイツ語）の文言で見分け、翻訳された git（`LC_ALL=fr_FR.UTF-8` など）では Git 管理外のフォルダで reject して `git-failed` になっていたため、子プロセスに渡す環境の写しだけを `buildModeGitEnv` で `LC_ALL=C` にし、`LANGUAGE` を外す（git の gettext は `LANGUAGE` を `LC_ALL` より優先する）。`process.env` は書き換えない。ほかの変数は除かず（`buildIsolatedGitEnv` の除き方は使わない）、simple-git の `env()` の環境の検査は許可して、親の環境を引き継ぐ今の判定のままにする。記録・一覧などのほかの git（リポジトリの方式の記録の `createRepoGit` を含む）は変えない（記録の `add -A` だけは、読めないフォルダの警告を見分けるため `buildModeGitEnv` を通した環境で動かす。「記録の git の場所と環境」。ローカルレビュー第 33 周の指摘 1）

方式は 3 種類の判別の共用体にする（`{ kind: 'repository' } | { kind: 'hidden-new' } | { kind: 'hidden'; gitDir: string }`、記録できないときは `unavailable`）。以後の手順は方式ごとの関数に分ける（今の 1 つの関数に分岐を足さない）。

### 区切りの写しの元（`base`）

`TakeBaselineOptions.baseIndexPath?: string` を `base?: BaselineCheckpointBase` に置き換える。

```ts
/**
 * 区切りの写しの元: 写す記録のインデックス(実行の区切りは直前の取れた記録、区別の判定の区切りは直前の判定の区切り)と、記録の隠れた
 * git の場所(リポジトリの方式は null)。組み立ては agentChangesRecord の checkpointBaseOf
 */
export interface BaselineCheckpointBase {
  indexPath: string
  gitDir: string | null
}
```

- 実行の区切り（registry の `addRun`）: `agentChangesRecord.ts` に `checkpointBaseOf(record)`（`{ indexPath: latestRecordedIndexPath(record), gitDir: record.baseline.gitDir }`）を足して渡す
- 判定の区切り（registry の `attributionContextOf` の `takeSnapshot`）: `agentChangesAttributionSync.ts` の `ctx.takeSnapshot(baseIndexPath)` の形は変えず、registry の包みが `checkpointBaseOf(record, baseIndexPath)`（インデックスだけを差し替える。`{ indexPath: baseIndexPath, gitDir: record.baseline.gitDir }`）にして渡す（SRP リファクタリングで、gitDir の決め方を `checkpointBaseOf` の 1 か所にまとめた）
- `gitDir` は記録の累積の始点の値を常に使う（区切りの記録の `gitDir` は始点と同じ値を持つ）

### 隠れた git の作成（新しいファイル `agentBaselineHiddenGit.ts`）

`createHiddenGit(tempDir, gitOptions): Promise<string>`（作った `gitDir` を返す。`gitOptions` は打ち切りと元の環境だけで、`config` は受け取らない）:

1. `git init --bare -q --template= <tempDir>/git` を cwd を `tempDir` にして実行する。環境は `buildBaselineGitEnv` と同じ除き方（拒否される変数・位置の変数・設定の組）で、`GIT_INDEX_FILE`・`GIT_DIR`・`GIT_WORK_TREE` を足さない（除く部分を `buildIsolatedGitEnv(source)` に切り出して共有する）。起動は `agentBaselineGit.ts` の `runIsolatedGit`（`--template=` を simple-git が拒否するため spawn。打ち切り・失敗の扱いは `runBaselineGitWithInput` と共有する）。打ち切りは `AGENT_BASELINE_GIT_TIMEOUT_MS`
2. 隠れた git の設定に `core.fsmonitor=false`・`gc.auto=0`・`maintenance.auto=false`・`core.hooksPath=<gitDir>/no-hooks`（作らない。存在しない絶対パス）・`core.autocrlf=false`・`core.safecrlf=false`・`core.ignoreStat=false`・`core.checkStat=default`・`core.trustctime=true`・`diff.autoRefreshIndex=true` の 10 個を書く（`git config`。環境の `GIT_DIR` で隠れた git を指す。値は main の定数と main が作ったパスだけ）。隠れた git の設定は利用者の大域の設定より優先されるため、大域の `core.hooksPath` の hook（特に index を書くたびに動く `post-index-change`）が隠れた git の命令で動かない（既存の保護の ref が `core.hooksPath=<noHooksDir>` で止めているのと同じ考え方。`agentChangesProtectionRef.ts` の `configOf`）。設定を書き終えるまでの `init`・`config` にも同じ値を `-c core.hooksPath=<gitDir>/no-hooks` で渡す（git 2.50.1 の `init` は `HEAD` を作るときに大域の `core.hooksPath` の `reference-transaction` の hook を 2 回動かす。Task 2a で実測）。`core.autocrlf=false`・`core.safecrlf=false` は、利用者の大域・システムの改行コードの設定で記録の内容と戻した後の内容が記録の時点のバイトと変わらないようにする（2026-10-15 のローカルレビュー第 5 周で追加）。この 2 つは命令の `-c`（`hiddenGitCommandConfig`）には足さない。`-c` は、利用者の命令を動かしうる設定（hook・fsmonitor）を親の環境の `GIT_CONFIG_PARAMETERS` に上書きされないための守りで、改行コードの設定は命令を動かさない（親の環境が改行コードを明示したときはそれに従う）。`core.ignoreStat=false`・`core.checkStat=default`・`core.trustctime=true`・`diff.autoRefreshIndex=true` は、利用者の大域の設定で変更の検出が緩まないようにする（ローカルレビュー第 6 周で追加。`-c` に足さない理由は改行コードと同じ）。この前に、`init` が書いたローカルの設定の鍵の名前を `git config --local --name-only --list -z` で読み（`--local` は大域・システム・`-c` を含めない）、`core.symlinks`・`core.ignorecase`・`core.precomposeunicode` のうち無い鍵に git の既定値（`true`・`false`・`false`。`HIDDEN_GIT_FILESYSTEM_DEFAULTS`）を書く（`init` が調べて書いた値は上書きしない。ローカルレビュー第 6 周で追加。決めたこと「ファイルシステムの性質」）
3. `<gitDir>/info` を `mkdir`（0700。再帰しない）し、`info/exclude` を `wx`・0600 で書く（中身は既定の一覧を 1 行ずつ。先頭に「prompt-ide が書いた既定の一覧」の注釈の行）
4. どこかで失敗したら例外にする（呼び出し側が記録の一時ディレクトリごと消して `git-failed`。打ち切りは `timeout`）

1・2 の命令の並び（引数と `GIT_DIR`）は `hiddenGitInitCommand()`・`hiddenGitLocalConfigNamesCommand(gitDir)`（出力は `parseConfigNames`）・`hiddenGitConfigCommands(gitDir, init が書いた鍵の名前)`、それらに付ける `-c` は `hiddenGitSetupCommandConfig(gitDir)`、`gitDir` は `hiddenGitDirOf(tempDir)` で組み立てる（どれも純粋。git の起動とファイルの書き込みだけを `createHiddenGit` が行う。SRP 第 3 周）

### 記録の git の場所と環境（`agentBaselineGit.ts`）

```ts
/** 記録の git の場所。gitDir が null ならリポジトリの方式(利用者の .git の object の DB を使う) */
export interface BaselineGitLocation {
  folderPath: string
  indexPath: string
  gitDir: string | null
}
```

- `BaselineGitLocation` は git の層（`agentBaselineGit.ts`）で定義し、`BaselineSnapshot` はこの形を満たす。git の起動の層は記録の手順（`agentBaselineSnapshot.ts`）を型でも参照しない（依存は記録 → git の一方向。SRP リファクタリング第 2 周で `Pick<BaselineSnapshot, …>` から変えた）

- `BaselineSnapshot` に `gitDir: string | null`（必須。「隠れた git の場所。null はリポジトリの方式」）を足す
- `buildBaselineGitEnv(source, location)`: 今の除き方の後に `GIT_INDEX_FILE` を足し、`location.gitDir` が文字列なら `GIT_DIR=<gitDir>`・`GIT_WORK_TREE=<folderPath>` を足す。除く判定は今どおり大文字小文字を問わない（Windows で `git_dir` などの別の綴りが残らない。L-079）。null なら今と同じ結果
- `createBaselineGit(location, options)`・`runBaselineGitWithInput(location, args, input, options)`・`runBaselineGitWithInputSync(location, ...)` は場所をまとめて受け取る（`folderPath`・`indexPath` の 2 つの引数をやめる）。`gitDir` は必須のため、呼び出し元を 1 つでも直し忘れると型検査で落ちる（L-060）

### 隠れた git の記録の手順（`takeBaselineSnapshot`）

リポジトリの方式は今の手順のまま。隠れた git は次の順にする（各 `await` の後で `checkpoint()`）。

1. 記録の一時ディレクトリを作る（`mkdtemp(join(tempRoot, baselineTempDirPrefix(instanceId)))`。0700）
2. 新規なら `createHiddenGit(tempDir)` で `gitDir` を作る。区切りなら `base.gitDir`
3. 写し: 新規は写さない（記録のインデックスは空から始める）。区切りは `copyIndexPreservingTimes(base.indexPath, indexPath, { required: true })`（今と同じ。無ければ例外で `git-failed`。L-002）
4. 未追跡の事前の検査: 隠れた git に空の index（`<tempDir>/empty-index`。作らない）を渡して `ls-files -z --others --exclude-standard` を数える（`inspectUntracked` に空の index の git を渡す。問い合わせと出力の解釈は `inspectUntracked` の 1 か所で、方式ごとの関数は問い合わせ先の git だけを選ぶ。SRP リファクタリング第 12 周。選択肢は打ち切りだけで、入れ子のリポジトリの HEAD は利用者の git の環境のまま問い合わせる。第 16 周。上限・5MB の除外・入れ子のリポジトリの扱いは同じ）。超えたら一時ディレクトリを消して `too-many-files`（件数・大きさを添える）
5. `add -A`: 今と同じ pathspec のファイルで渡す。区切りでは、写しの元から引き継いだ記録しないパス（`removeInheritedPaths`）と、記録の中で今 ignore されるパスを外す。後者は利用者の追跡済みの一覧を空として求める（記録の中の ignore されるパスをすべて外す。`inheritedIgnoredPaths` の `repoGit` の問い合わせを「利用者の追跡済みのパスの集合」を返す関数の注入に変え、隠れた git では空の集合を渡す）。区切りでは、引き継いだ入れ子のリポジトリの gitlink（`160000`。利用者が追跡しているものを除く。隠れた git ではすべて）も `add -A` の前に外して入れ直させる（`inheritedNestedRepoPaths`。両方の方式。「セキュリティ」の入れ子のリポジトリの行）。区切りの取り外しは、先に `update-index --force-remove` で ignore されるパスと gitlink を外し、その後に記録しないパスを `git rm -r --cached` で外す。`git rm` は gitlink を外すとき、記録のインデックスと作業ツリーの `.gitmodules` が違えば `--cached`・`-f` でも exit 128 で止まるため（HEAD が生まれていない状態に戻った入れ子のリポジトリは `skippedRepos` に入る。ローカルレビュー第 14 周の指摘 1。git 2.50.1 で実測）、gitlink は `.gitmodules` を見ない `update-index --force-remove` だけで外す（記録しないパスのうち利用者から見て未追跡の gitlink は、`git rm` の前に外れている）。`add -A` は `runBaselineGitDetectingUnreadablePath` で動かし、読めないフォルダの警告か、実行できないフォルダの中の追跡済みのファイルの `Permission denied` の行が出たら例外にして `git-failed` にする（読めないファイルは `add -A` が exit 128 で失敗するのと揃える。後始末は 10. の経路。両方式・始点と区切り。ローカルレビュー第 33 周の指摘 1・第 35 周の指摘 1）
6. `ignoredAtBaseline`: 今と同じ（隠れた git で問い合わせるため `info/exclude` も効く）
7. HEAD: null（`readRecordHead`）
8. `write-tree`
9. 記録を返す（`gitDir` を持つ）
10. 失敗・取り消しのとき: 今どおり自分の一時ディレクトリだけを消す。新規なら隠れた git も一時ディレクトリの中なので一緒に消える。区切りは自分の一時ディレクトリ（記録のインデックス）だけを消し、共有の隠れた git には触れない（区切りの `add` が書いた blob は到達できない object として残り、記録を捨てるときに消える）

### 記録の一時ディレクトリの名前と起動時の掃除（新しいファイル `agentBaselineTempSweep.ts`）

- 接頭辞の定数 `AGENT_BASELINE_TEMP_DIR_PREFIX = 'prompt-ide-agent-baseline-'` を `agentBaselineSnapshot.ts` から移し、`baselineTempDirPrefix(instanceId)` は `prompt-ide-agent-baseline-<instanceId>-` を返す（`mkdtemp` が 6 文字を足す）。名前の解釈の正規表現も同じ定数から組み立てる（SRP リファクタリング第 12 周）
- `TakeBaselineOptions.instanceId: string` を必須で足す。`ipcHandlers.ts` は今の保護の `instanceId`（`createProtectionInstanceId(process.pid, …)`）を 1 回だけ作り、registry の保護の依存と `takeSnapshot` の包みの両方に同じ値を渡す
- 名前の解釈 `parseBaselineTempDirName(name)`（純粋）: `^prompt-ide-agent-baseline-([1-9][0-9]{0,9})-([0-9a-f]{8})-[A-Za-z0-9]{6}$` に一致し、pid が `Number.isSafeInteger` で 1 以上 2^31−1 以下のときだけ `{ pid, instanceId }`。それ以外（古い形の名前を含む）は null（触らない。L-020・L-046）
- 自分のものの判定 `isOwnBaselineTempDir(stat, { uid, platform })`（純粋）: `lstat` の結果がディレクトリでシンボリックリンクでなく、Windows 以外は `uid` が自分と一致し `mode & 0o077` が 0（L-437）
- 名前だけで決まる候補の条件 `staleCandidatePidOf(name, instanceId)`（純粋）: 名前を解釈できて、自分の `instanceId` でなければ確かめる pid、それ以外は null
- `sweepStaleBaselineTempDirs({ tempRoot, instanceId, isProcessAlive })`: `tempRoot` の直下を `readdir` し、`staleCandidatePidOf` が pid を返し、`isProcessAlive(pid)` が偽（`isProcessAliveOnThisMachine`。`EPERM` は生きているとみなす）で、`lstat` が自分のものと分かるものだけを `rm(recursive, force)` する。1 つの失敗は握って次へ進む（L-010）。消した数を返す（テスト用）
- 呼ぶのは起動のとき 1 回（`ipcHandlers.ts` で registry を作った後に `void sweepStaleBaselineTempDirs(...).catch(() => undefined)`。待たない）。自分の `instanceId` の記録は掃除の対象にならないため、最初の記録と並んでも消さない
- 一時ディレクトリの親（`tempRoot`）は `ipcHandlers.ts` が `tmpdir()` を 1 回だけ読み、`takeSnapshot` の包みと掃除の両方に同じ値を渡す（掃除が記録の側の既定値に頼らない。SRP リファクタリング第 2 周）

## IPC と型

## テスト方針

vitest。実 git の統合テストは既存の補助（`helpers/realGitRepo.ts`・`helpers/agentBaselineFixtures.ts`。大域の設定を隔離した `HOME`）を使い、Git 管理外のフォルダを作る補助（`createAgentNonGitFolder`）を足す。隠れた git の作成・一連の操作の統合テストも、Git 管理外のフォルダと隔離した `HOME` をこの補助で作る。戻す・取り消しの統合テストが共有する戻す操作の文脈（`makeRevertContext`）とハンクの内容・パッチ（`numberedLines`・`firstHunkPatch`）も `agentBaselineFixtures.ts` に置く（SRP リファクタリング）。

## 既知の制約（ROADMAP・実機テスト仕様書に反映する）

- Git 管理外のフォルダで `too-many-files` が出た後に、パネルの `リポジトリを初期化` で初期化しても、理由の文は次の `実行` まで残り、`いまから記録する` は出ない（`too-many-untracked` と同じく、理由が出ている間は `実行` で送り直して記録を始める）
- Git 管理外のフォルダでは、フォルダ全体（`.gitignore`・既定の一覧・git の大域の除外で除いたものを除く）が上限の対象になる。ignore されていないファイルが 5,000 件・合計 100MB を超えると記録しない。5MB を超えるファイルは、記録の前からあったものも含めて記録しない（一覧には記録していない旨の行で出て、エージェントが変えても戻せない。リポジトリの方式では追跡済みのファイルは大きさに関わらず戻せる）。大きなフォルダ（ホームのフォルダなど）は記録できないか、未追跡の検査に時間がかかって打ち切られる（10 秒）。その場合、送るたびに検査し直すため、`実行` の送信が最大 10 秒待つ
- 既定の一覧（`node_modules/`・`.venv/`・`venv/`・`__pycache__/`・`.next/`・`dist/`・`build/`・`target/`・`.DS_Store`・`Thumbs.db`）の中の変更は一覧に出ず、戻せない。フォルダの `.gitignore` の `!dist/` などで打ち消せる
- 記録の内容はアプリの一時領域（OS の一時ディレクトリの中）に置き、ディスクを使う（5,000 件の小さなファイルで約 20MB）。`確認を終える`・アプリの終了・次の起動の掃除で消える。古い版の名前（pid を含まない）の一時ディレクトリと、取り消しの控えの一時ディレクトリは、今までどおり OS の掃除に任せる
- Linux で `/tmp` が tmpfs の環境では、記録の内容がディスクではなくメモリを使う（ウィンドウごとに増える）。systemd-tmpfiles などが `/tmp` の古いファイルを消す環境（Fedora などの既定は 10 日）や、macOS（OS の定期の掃除が一時ディレクトリの 3 日より古いファイルを消す）では、記録を長く開いたままにすると隠れた git のオブジェクトが消え、以後の一覧・区切り・diff・戻すが失敗しうる（中身を失う側には倒れず、戻す前の確かめで拒否する。未確認。そのときは `確認を終える` で終えて記録し直す）
- `.env` など ignore されていない秘密のファイルも、記録のために一時領域（0700）へ写る
- 隠れた git は、利用者の大域・システムの `core.autocrlf`・`core.safecrlf` では改行コードを変換しない（隠れた git の設定に `core.autocrlf=false`・`core.safecrlf=false` を書き、ハンクで戻す `git apply` も隠れた git の設定で動かす）。変更の検出も、利用者の大域の `core.ignoreStat`・`core.checkStat`・`core.trustctime`・`diff.autoRefreshIndex` で緩めない。フォルダに置いた `.gitattributes` の `text`・`eol`（と大域の `core.attributesFile`。`core.eol` はこれらの属性と組み合わさったときに効く）による変換・`ident`・`working-tree-encoding` は利用者の意図として今も効き、その場合は戻した後の内容が記録の時点とバイト単位で違いうる
- 記録中に `git init` しても、その記録は `確認を終える` まで一時領域の記録のまま（HEAD の帯は出ない）。次の記録からリポジトリの記録になる
- Git 管理外のフォルダの記録では、HEAD の帯は出ない
- 隠れた git のファイルシステムの性質（大文字小文字の区別・シンボリックリンク・実行ビット）は、一時ディレクトリで git が調べた値（調べて書かなかった鍵は git の既定値。利用者の大域の値は使わない）を使う。macOS で大域に `core.precomposeunicode` があると `init` が調べないため、隠れた git は既定値の `false`（NFD の名前を NFC に直さない）で記録・一覧・戻すを一貫して扱う。開いたフォルダが一時ディレクトリと性質の違うボリューム（大文字小文字を区別する外付けのディスク・シンボリックリンクを持てない FAT など）にあると、記録・戻すの判定がずれる・リンクを戻せないことがある（未確認）。例: 大文字小文字を区別するボリュームに `README.md` と `readme.md` があると、大文字小文字を区別しない設定の隠れた git では片方しか記録されず、記録の前からあったもう片方が「追加」に見え、`すべて戻す` でゴミ箱へ移りうる（ゴミ箱から戻せる）
- Windows では未確認（`GIT_DIR`・`GIT_WORK_TREE` に別のドライブのパスを渡す場合を含む）
- `.git` の中・bare リポジトリのフォルダでは記録しない。リポジトリのサブフォルダでは今までどおり使えない
- `.git` の中・bare リポジトリのフォルダでも、記録の前のセクションには Git 管理外のフォルダと同じ注記（`Git 管理外のフォルダのため、記録はアプリの一時領域に置きます（node_modules などは記録しません）`）と `いまから記録する` が出る（renderer は開いたフォルダが bare・`.git` の中かを知らない）。押すと `Git のデータのフォルダ（.git の中・bare リポジトリ）では、エージェントの変更を記録できません` に変わる（表示だけの食い違い。記録はしない）
- 読めないファイル・フォルダがあると記録できない（git を実行できない、と出る。読めないフォルダは以前は黙って記録から外れ、後で読めるようになると「追加」として一覧に出て、戻すとゴミ箱へ移っていた。ローカルレビュー第 33 周の指摘 1 で修正。読めるが実行できないフォルダ〈`chmod 600` など〉の中の追跡済みのファイルは、以前は古い内容のまま記録され、権限を戻すと記録の前からの変更がエージェントの変更として出ていた。ローカルレビュー第 35 周の指摘 1 で修正。フォルダの外の大域の除外・属性のファイル〈`~/.config/git/ignore` など〉が読めないだけでは記録は止まらない。第 35 周の修正の後は、この警告でどのフォルダでも記録が失敗していた。ローカルレビュー第 36 周の指摘 1 で修正）
- Git 管理外のフォルダの中のリポジトリ（入れ子のリポジトリ）は、今までどおり変更を戻せない
- 入れ子のリポジトリ・サブモジュールの中の未コミットの変更（作業ツリー・index の変更）は一覧に出ない（HEAD が動いたときだけ `M` で出る。入れ子のリポジトリの中の命令を動かさないため。リポジトリの方式も同じ）。利用者が追跡しているサブモジュールは、記録の `add -A` が今までどおり中を調べる（そのサブモジュールの設定の filter などが動き、その index を書き直しうる。利用者のリポジトリの `git add -A` と同じ）
- 開いたフォルダが OS の一時ディレクトリそのもの（`$TMPDIR`）かその親だと、記録の一時ディレクトリ自体が作業ツリーに入り、一覧に「追加」として出て、すべて戻す でゴミ箱へ移りうる（まれ）
- 大域の `core.sharedRepository=group` が隠れた git に引き継がれる（親の一時ディレクトリが 0700 なのでほかの利用者からは見えない）
- 利用者が `safe.bareRepository=explicit` を設定していると、bare リポジトリのフォルダは `inside-git-dir` ではなく `git-failed` になる（隠れた git で記録しない安全側）

## 未確認事項（実装の最初に確かめる）

1. 利用者の大域の設定に `core.fsmonitor=true` があるとき、隠れた git の `core.fsmonitor=false` が効き、記録・一覧の後に fsmonitor の daemon が起動していない（`git fsmonitor--daemon status` を隠れた git の環境で実行する）
2. ignore されていないファイルが 5,000 件近く・合計 100MB 近くのフォルダで、累積の始点にかかる時間と隠れた git の大きさ（設計時は 5,000 件の小さなファイルで 1.7 秒・20MB。確認の結果 12）。打ち切り（10 秒）に近ければ記録する
3. `git init` が大域の `init.defaultObjectFormat=sha256`・`init.defaultRefFormat=reftable` を引き継いでも、記録・一覧・戻す・tree どうしの比較が動く（object の ID の形は今の `OBJECT_ID_PATTERN` が 64 桁を受け付ける）

結果が想定と違えば、設計書の該当の節（「隠れた git の作成」「既知の制約」）を直してから進める。
