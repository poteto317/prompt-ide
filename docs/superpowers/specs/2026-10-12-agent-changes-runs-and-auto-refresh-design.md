- 前提の設計書: `2026-10-06-agent-changes-review-design.md`（記録のインデックス・一覧・diff・戻す・「いつ完了とするか」の契機の 4 つ・「この機能の後の候補」）、`2026-10-04-agent-terminal-mvp-design.md`（IPC の安全策）、活動の判定と完了・許可待ちの通知（`lib/agentActivity.ts`・`lib/agentNotificationEvents.ts`）

## 目的

エージェントの変更の確認（2026-10-06 の設計書）は、最初の `実行` から `確認を終える` までの変更を累積して見せる。続けて何回も `実行` すると、どの指示でどのファイルが変わったかが一覧から分からない。また、一覧は `変更を確認`・`更新`・Git の操作・セッションの終了でしか取り直さず、エージェントが作業を終えた・許可を求めて止まった・利用者が別のアプリから戻った、という「見たい時」に古いままである。

この機能では、プロンプトを送るたびに「実行の区切り」の記録を足し、一覧の上の選択で「すべて（累積）」と「実行 N」を切り替えて、その実行で変わったファイルと差分だけを見られるようにする。あわせて、活動の判定（完了・許可待ち・確認待ち）とウィンドウのフォーカスの復帰を契機に、記録がある間だけ一覧を自動で取り直す。

## 決めたこと（利用者の確認済み）

| 項目         | 決定                                                                                                                                                                                           |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 実行の区切り | プロンプトを送るたびに区切る。送る直前に毎回新しい記録を取り、実行 1・実行 2…と番号を振る。今の「最初の実行からの累積」も引き続き見られる                                                      |
| 比べ方       | 一覧の上の選択で「すべて（累積）」「実行 1」「実行 2」…を選ぶと、その実行で変わったファイルと差分だけが出る。実行 N の範囲は「実行 N の開始の時点 → 次の実行の開始の時点」。最後の実行は今まで |
| 戻す操作     | 今どおり「すべて（累積）」の表示でだけ使える。実行ごとの表示は見るだけ                                                                                                                         |
| 保つ数       | 新しい方から 10 件。11 件目を取ったら、一番古い実行の区切りを捨てる（累積の始点は残す）                                                                                                        |

| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 記録の持ち方                      | main の registry の 1 所有者の記録を「累積の始点（今の `BaselineSnapshot`）+ 実行の一覧（最大 10 件）」に広げる。各実行は開始の区切り（記録のインデックス 1 つ）を持つ。実行 N の終わりは実行 N+1 の開始の区切り（最後の実行は作業ツリー）で、終わりの記録は別に持たない                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | 区切りを「開始」だけにすると、隣り合う実行が同じ記録を共有し、記録の数は実行の数と同じで済む。累積の始点を実行の一覧と別に持てば、古い実行を捨てても累積の表示と戻す操作は変わらない                                                                                                                                                                                                                                                                |
| 送信の前の依頼と手動の依頼の区別  | `agentChanges:begin` に必須の引数 `trigger: 'send' \| 'manual'` を足す。`send`（プロンプトの `実行` の直前）: 記録が無ければ累積の始点を取り、それを実行 1 の開始にする。記録があれば区切りを取り、新しい実行を足す。`manual`（`いまから記録する`）: 今と同じ（記録が無ければ始点を取る。実行は足さない。記録があれば何もしない）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | 区切りは「プロンプトを送るたび」なので、手動の記録の開始は実行に数えない。引数を省略した依頼を既定の値に流さず例外にする（L-044）。`いまから記録する` の後の最初の `実行` が実行 1 になり、その前にターミナルへ直接打ち込んだ指示の変更は累積にだけ出る                                                                                                                                                                                             |
| 区切りの作り方                    | 今の `takeBaselineSnapshot` を再利用する。違いは 2 つ: (a) 写しの元を `.git/index` ではなく、直前の取れた記録（直前の区切り、無ければ累積の始点）の記録のインデックスにする（`baseIndexPath` の引数）。未追跡の事前の検査（件数・大きさの上限と除外の判定）は、区切りでも累積の始点と同じく利用者の index 基準で行い、除外になったパスと、利用者から見て未追跡で今 ignore されるパスが写しの元から引き継いだエントリに残っていれば記録のインデックスから外す。(b) 記録のインデックスから `git write-tree` で tree を作って記録に控える（累積の始点も同じく控える）。写しの更新時刻は写しの元にそろえる（ブランチ全体の最終レビューで追加。`copyFile` は macOS で更新時刻を引き継がず、写しが今の時刻になると git の racy-git の守り〈index の更新時刻以上の更新時刻を持つエントリは中身まで比べる〉が外れ、写しの元を書いたのと同じ秒に同じ大きさで書き換えた変更を見落としていた） | (a) 直前の記録の stat の情報が使え、変わっていないファイルを読み直さない。検査を記録のインデックスで行うと、前の記録に未追跡として入ったファイルが後で 5MB を超えても追跡済みに見えて除外されず、送るたびに丸ごと hash し、`.git/index` から作った場合と tree が違ってしまうため、検査は利用者の index にそろえる（Task 1 のレビューで変更）。(b) 途中の実行の比較は tree と tree の比較で、利用者の index を変えない（2026-10-06 の確認の結果 13） |
| 区切りの直列                      | 区切りの取得は所有者の列（`withRecord` と同じ `KeyedSerialQueue`）の中で行う。累積の始点を取得中に `send` の依頼が来たら、合流せずにその完了を待ってから列に並べ、区切りを取って新しい実行にする（始点が取れなければ何もしない）。`await` のたびに世代を比べ、変わっていれば一時ディレクトリを消して捨てる（パターン 141）                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | 写しの元（直前の記録のインデックス）を、同じ所有者の一覧・diff・戻すの git が同時に読み書きしないようにする。送った順と実行の番号の順を一致させる（renderer の 10 秒の打ち切りで送信が先へ進み、次の送信の依頼が前の区切りより先に main に届いても、列の順で番号を振る）                                                                                                                                                                            |
| 実行の番号と ID                   | 実行は `runId`（所有者ごとに単調に増える正の整数。記録を捨てても戻さない）と `number`（その記録の中の 1 からの番号。表示用）を持つ。renderer が範囲に渡すのは `runId`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | `確認を終える` の後の新しい記録でも番号は 1 から振り直すが、`runId` は前の記録と重ならないため、古い写しから届いた依頼が新しい記録の別の実行を指すことが無い（L-037）                                                                                                                                                                                                                                                                               |
| 10 件を超えたとき                 | 新しい実行を一覧に足した後に、11 件目になっていれば一番古い実行を一覧から外し、その開始の区切りの一時ディレクトリを列の中で消す。開始が累積の始点の実行（記録が無い状態から送った実行 1）を外すときは、始点は消さない。記録できなかった実行（下の行）も 1 件に数える                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | 消すのは新しい実行の結果が決まった後にする（L-003）。消す対象は自分が作った区切りの一時ディレクトリだけで、累積の始点と共有している記録は消さない（L-004）。番号を飛ばさずに数えるため、記録できなかった実行も一覧に残す                                                                                                                                                                                                                            |
| 区切りを取れなかったとき          | 送信は止めない（今の始点と同じく、記録はおまけ）。実行は一覧に足し、`start: failed`（理由は `AgentChangesUnavailableReason` の `too-many-untracked`・`timeout`・`git-failed`）にする。その実行と、終わりがその区切りになる 1 つ前の実行は選べない。選択の項目に理由を出す                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | 終わりが無い実行を「今まで」や次の取れた区切りまでに読み替えると、別の実行の変更が混ざった一覧を「実行 N」として見せる（L-002）。番号を詰めると、利用者が数えた送信の回数と番号がずれる                                                                                                                                                                                                                                                             |
| 範囲の求め方                      | 累積: 今と同じ（累積の始点 → 作業ツリー）。最後の実行: 開始の区切りを累積の始点の代わりに渡して、今の一覧・diff（`collectAgentChangeEntries`・`getAgentChangeDiff`）をそのまま使う。途中の実行: 開始の区切りの tree → 次の区切りの tree の `git diff-tree`・`git diff <tree> <tree>`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | 最後の実行の終わりは作業ツリーで、累積と同じ比べ方（記録のインデックスと作業ツリー）になる。途中の実行は両端が記録で、記録のインデックスどうしは git で直接比べられないため tree にする                                                                                                                                                                                                                                                             |
| HEAD が変わった帯                 | 累積は今どおり（始点の HEAD と今）。実行 N は開始の区切りの HEAD と終わり（次の区切りの HEAD、最後の実行なら今の HEAD）を比べ、違えば `この実行の間に HEAD が変わりました（コミット・ブランチの切り替えなど）` を出す                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | 累積の `headChanged` と同じ考え方を範囲の両端に当てる。実行ごとの表示は戻せないため、「戻すのはファイルの内容だけです」は付けない                                                                                                                                                                                                                                                                                                                   |

| diff タブと範囲                   | エージェントの変更の diff タブはパスごとに 1 つのまま（タブの鍵に範囲を足さない）で、セクションで選んでいる範囲に従う。ラベルは `<path> (エージェントの変更・実行 N)`（累積は今どおり `<path> (エージェントの変更)`。N は diff の内容を取った範囲から取る）。diff の内容は取った範囲と組で持ち、ハンクの `このハンクを実行前に戻す` は内容の範囲が累積のときだけ出す                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | タブの鍵に範囲を足すと、同じパスのタブが範囲ごとに増え、「一覧から消えたパスのタブを閉じる」の判定が今の選択の一覧と合わなくなる。内容と範囲を組にすれば、範囲を切り替えた直後に古い内容が残っていても、累積でない内容からハンクを戻す依頼を作らない                                                                                                                                                                                                |

## 範囲

含めるもの:

- プロンプトの `実行` の直前の実行の区切りの記録（main の registry・記録の取得）と、10 件の保持
- 一覧・diff の範囲の指定（累積・実行 N）と、実行の一覧の受け渡し（IPC・型・preload）
- 戻す系の IPC の範囲の検査（累積だけを受け付ける）
- セクションの範囲の選択・実行の範囲での表示（見出し・空の文言・HEAD の帯・戻すボタンの無効の理由）・diff タブの範囲の表示
- 活動の出来事とウィンドウのフォーカスの復帰による、一覧の自動の取り直し（合流・上限付きのデバウンス）

含めないもの（頼まれていない。ROADMAP の「エージェントの変更の確認の拡張」に残す）:

- 戻した操作の取り消し（undo）
- `claude` の hooks で利用者の編集と区別すること
- Git 管理外のフォルダでの記録
- 記録の blob・tree を gc から守ること
- 任意の 2 つの記録の比較（実行 1 → 実行 3 など）、実行ごとの戻す操作
- 自動の取り直しでの git status（ソース管理の一覧）の取り直し、実行中の逐次の更新

## 記録の持ち方（main）

### 記録の中身の変更

registry の `records: Map<ownerId, BaselineSnapshot>` を `Map<ownerId, AgentChangesRecord>` に変える。

| 項目         | 内容                                                                                                                                                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `baseline`   | 累積の始点（今の `BaselineSnapshot`。`tree` を足す）。一覧・diff・戻すの累積の範囲はこれを使う                                                                                                                   |
| `runs`       | 実行の一覧（古い順・最大 10 件）。各要素は `runId`・`number`・`start`                                                                                                                                            |
| `start`      | `{ kind: 'baseline' }`（開始が累積の始点。記録が無い状態から送った実行 1）・`{ kind: 'snapshot'; snapshot: BaselineSnapshot }`（区切り）・`{ kind: 'failed'; reason: AgentChangesUnavailableReason; startedAt }` |
| `nextNumber` | 次の実行の番号（記録の中で 1 から）                                                                                                                                                                              |

- `BaselineSnapshot` に `tree: string`（記録のインデックスから `git write-tree` で作った tree の ID）を足す。`takeBaselineSnapshot` の最後（HEAD を控えた後）で作る。`write-tree` の失敗は今の記録の失敗と同じ扱い（`git-failed`・`timeout`）にする
- 所有者ごとの `runId` の次の値は、記録とは別の `Map<ownerId, number>` に持ち、`clear` でも戻さない（所有者の文脈の終わりでも戻さない。値は増えるだけなので、捨てる必要が無い）

### 依頼の流れ（`begin(ownerId, folderPath, trigger)`）

1. `trigger === 'manual'`: 今と同じ（記録があれば `recording` を返す。取得中の始点の依頼があれば合流する。無ければ始点を取る）。実行は足さない
2. `trigger === 'send'` で記録が無い・取得中の始点も無い: 始点を取る（今の流れ）。取れたら `runs = [{ runId, number: 1, start: { kind: 'baseline' } }]` にする
3. `trigger === 'send'` で始点の取得中: 合流しない。その完了を待ち、取れなかった（`none`・`unavailable`）ならその状態を返す。取れたら 4 へ進み、区切りを取って新しい実行にする（取得中の始点が `send` の依頼なら、その実行 1 の次の実行 2。`manual` の依頼なら実行 1）。始点の取得中に 2 つ目の `send` が届くのは、1 つ目の送信が待ちの上限（10 秒）で先へ進み、利用者が続けて送ったときだけで（`useAgentPromptSender.send` は `sendingRef` で二重の送信を同期で止め、StrictMode もコールバックを二重に呼ばない）、これも 1 回の送信として数える（送った回数と番号を一致させる）
4. `trigger === 'send'` で記録がある: 所有者の列に並べ、列の中で次を行う
   1. 記録のフォルダが依頼のフォルダと違う・世代が変わった → 何もせず `none`（今の `withRecord` と同じ照合）
   2. 写しの元を決める: 実行の一覧を新しい方から見て、最初の `start` が `snapshot`・`baseline` の記録のインデックス（無ければ累積の始点）
   3. `takeBaselineSnapshot(folderPath, { baseIndexPath, isCanceled })` で区切りを取る
   4. 取れた → `start: { kind: 'snapshot', snapshot }`。取れなかった（`unavailable`）→ `start: { kind: 'failed', reason, startedAt }`。取り消された（`canceled`・世代が変わった）→ 一時ディレクトリを消して `none`
   5. 実行を一覧の末尾に足す（`number = nextNumber++`・`runId` を振る）
   6. 11 件になったら一番古い実行を一覧から外し、その `start` が `snapshot` なら一時ディレクトリを消す（`baseline`・`failed` は消すものが無い）
   7. `recording`（実行の一覧を含む）を返す

- 取得中の始点の依頼への合流（今の `pending`）は `manual` の依頼だけで、世代とフォルダが同じときだけ（今と同じ）。`send` の依頼は合流せず、区切りの依頼どうしも合流しない（送信ごとに 1 つの実行）。始点を取り終えたときに実行 1 を足すかは、始点の取得を始めた依頼の `trigger` で決める（取得の処理の中で持つ値で、`pending` には `trigger` を持たせない）
- `clear`・所有者の文脈の終わり: 世代を進め、記録を外し、列の後ろで累積の始点と、すべての実行の `snapshot` の一時ディレクトリを消す。1 つの削除が失敗しても残りを試す（`removeBaselineDir` は失敗を握る。L-010）
- `close`（アプリの終了）: すべての一時ディレクトリを同期で消す
- 記録のフォルダと今の許可のフォルダが違うときの扱い（`currentRecord` で捨てる・`withRecord` では捨てない）は今のまま

### `takeBaselineSnapshot` の変更

- 引数 `baseIndexPath?: string` を足す。指定があれば、`.git/index` の代わりにそのファイルを写す（無ければ例外。空から始めない。写しの元が消えているのは記録の一時ディレクトリが失われた異常で、空から始めると全ファイルを追加として記録する〈L-002〉。`git-failed` にする）
- 写した直後に、写しの元（`baseIndexPath` か `.git/index`）の atime・mtime を写しへ `utimes` で引き継ぐ（racy-git の守りを写しの元と同じにする。空から始めるときは不要。`stat`・`utimes` の失敗は `git-failed` で、一時ディレクトリを消す。ブランチ全体の最終レビューで追加）
- 未追跡の事前の検査（`ls-files -z --others --exclude-standard`。件数・大きさの上限と除外の判定）は、`baseIndexPath` の指定があっても利用者の index で問い合わせる（累積の始点と同じ基準）。区切りでは、除外になったパス・記録しない入れ子のリポジトリのパスを、記録のインデックス（写しの元から引き継いだエントリ）から `git rm -r -f --cached --ignore-unmatch` で外す（`GIT_INDEX_FILE` は記録のインデックス。利用者の index は触らない）。これで `.git/index` から作った場合と同じ tree・`excluded` になる（Task 1 のレビューで変更。記録のインデックスで問い合わせると、前の記録に入った小さいファイルが 5MB を超えても除外されなかった）。あわせて、記録のインデックスで追跡中で今の規則で ignore されるパス（記録のインデックスの `ls-files -z --cached --ignored --exclude-standard`）のうち、利用者の index（`ls-files -z --cached`）に無いものも外し（数に上限が無く、`git rm --pathspec-from-file` はエントリの数 × pathspec の数の時間になって数万件で打ち切りを超えるため、index のエントリと完全に一致するパスとして `git update-index -z --force-remove --stdin` に NUL 区切りで渡す。git は外すたびに後ろのエントリを詰めるため、index の並び〈名前の UTF-8 のバイト列の順〉の降順に渡す〈git 2.50.1・macOS の実測で 30 万件の削除は昇順 5.37 秒・降順 0.11 秒〉。除外・入れ子のリポジトリのパスはフォルダの下のエントリも外すため `git rm -r` のまま）、`ignoredAtBaseline` も `.git/index` から作った場合とそろえる（ローカルレビューで追加。前の記録に未追跡として入った後に `.gitignore` に足したファイル・利用者が `git rm --cached` してから ignore したファイルが記録のインデックスに残り、実行ごとの一覧に ignore 済みのファイルの `M`・`D` が通常の行として出ていた）
- 最後に `write-tree` を記録のインデックスで実行し、`tree` を控える
- 最上位のフォルダの確認・打ち切り（git のコマンドごとに 10 秒）・取り消し（`checkpoint`）は今のまま

## 範囲ごとの一覧と diff（main）

### 範囲の解決

handler は `withRecord` の中で、受け取った範囲を記録から次のどれかに解決する（`agentChangesScope.ts` の純粋な関数 `resolveAgentChangesScope(record, scope)`）。

| 範囲                              | 解決                                                  |
| --------------------------------- | ----------------------------------------------------- |
| `all`                             | `cumulative`（`record.baseline`）                     |
| `run` で `runId` が一覧に無い     | `unavailable: run-missing`                            |
| `run` で開始が `failed`           | `unavailable: start-not-recorded`                     |
| `run` で次の実行の開始が `failed` | `unavailable: end-not-recorded`                       |
| `run` で最後の実行                | `toWorktree`（開始の記録。`baseline` なら累積の始点） |
| `run` で途中の実行                | `between`（開始の記録と、次の実行の開始の記録）       |

### 一覧

- `cumulative`・`toWorktree`: 今の `listAgentChanges(snapshot)` をそのまま使う（記録しなかったファイル・ignore 済み・新しいフォルダの 1 行・500 行の打ち切り・HEAD の比較を含む）
- `between`: 新しい関数 `listAgentChangesBetween(start, end)`
  - `git diff-tree -r -z --name-status --no-renames <start.tree> <end.tree>`（利用者の index を読まない）で `A`・`M`・`D`・`T` の行を作る（`isDirectory` は常に false。新しいフォルダを 1 行にまとめない）
  - 両端のどちらかで記録しなかったパス（`excluded`・`skippedRepos`・`ignoredAtBaseline`〈フォルダは配下も〉）は、tree の差分の行から外し、両端の控え（有無・大きさ・更新時刻）で変わったと分かるものだけを `notRecorded` の行として足す（`excluded` は大きさ・更新時刻の控えがあるため、終わりにだけある → `A`、始まりにだけある → `D`、両方にあって大きさか時刻が違う → `M`。始まりで記録していて終わりで除外した・その逆も `M` の `notRecorded`。`ignoredAtBaseline`・`skippedRepos` は大きさと時刻の控えが無いため、有無だけで見て、終わりにだけある → `A`、始まりにだけある → `D` の `notRecorded` にし、両方にあるときは出さない〈中身が変わっても分からない。既知の制約〉）
    > 計画の時点で変えた細部（実装プラン `2026-10-12-agent-changes-runs-and-auto-refresh.md`）: `ignoredAtBaseline` は、片方の端にだけあっても行にしない（累積の一覧と同じく、ignore されたファイルの出現・削除は出さない）。`A`・`D` の行にするのは `skippedRepos`（コミットの無い入れ子のリポジトリ）だけ。tree の差分に出たパスのうち、どちらかの端で記録しなかったものは `M` の `notRecorded` の 1 行にする。
  - 500 行で打ち切り、`headChanged` は `start.head !== end.head`
- 結果の型 `AgentChangesListResult` は次の 3 つにする
  - `{ kind: 'none' }`
  - `{ kind: 'recording'; startedAt; runs; scope; …AgentChangesList }`
  - `{ kind: 'scope-unavailable'; startedAt; runs; scope; reason: 'run-missing' | 'start-not-recorded' | 'end-not-recorded' }`

### diff

- `cumulative`・`toWorktree`: 今の `getAgentChangeDiff(snapshot, path)`
- `between`: `git diff <patchFormatArgs> <start.tree> <end.tree> -- ':(literal)<path>'`（`getDiff` と同じ引数・同じ大きさの上限。追加・削除のファイルも git の出力のまま）。両端のどちらかで記録しなかったパスは `NOT_RECORDED_DIFF_MESSAGE` を返す
- `unavailable`: 例外（下の「エラー処理」の文言）
- 記録の blob・tree が消えていて（`git gc --prune=now` など）`diff-tree`・`diff` が `fatal: unable to read` で失敗したら、今と同じ `実行前の内容が見つかりません（git gc などで消えた可能性があります）` に置き換える

### 共有の型（`src/shared/types/agentChanges.ts`）

- `AgentChangesRun = { runId: number; number: number; startedAt: number; endedAt: number | null; availability: { kind: 'available' } | { kind: 'start-not-recorded'; reason: AgentChangesUnavailableReason } | { kind: 'end-not-recorded' } }`（`endedAt` は次の実行の開始の時刻。最後の実行は null。選べるかは main が決め、renderer は表示だけに使う）

### 入力の検証（`agentChangesPayloadParser.ts`）

- `parseAgentChangesBeginTrigger(value)`: `'send'`・`'manual'` 以外（`undefined` を含む）は例外
- `parseAgentChangesScope(value)`: プレーンなオブジェクトでない・キーが許可リスト（`all` は `kind` だけ、`run` は `kind`・`runId` だけ）の外・`kind` が列挙の外・`runId` が `Number.isSafeInteger` でない・1 未満、はどれも例外
- `parseRevertScope(value)`: `parseAgentChangesScope` の後、`kind !== 'all'` なら `AGENT_CHANGES_REVERT_SCOPE_MESSAGE` の例外
- 検証の順序: 送信元のメインフレームの確認 → 範囲（と既存の引数）の検証 → フォルダ → パスの検証 → 記録の列（今の `withRecordAtPath` の順序に範囲の検証を足す。検証の失敗は列に入る前に拒否する）

## renderer

### 記録の写しと範囲（`useAgentChanges`）

- `AgentChangesView` の `recording` に `runs: AgentChangesRun[]` を足し、`list` を `AgentChangesViewList | null` にする。`AgentChangesViewList` は `kind` で分ける: `{ kind: 'listed'; scope: AgentChangesScope } & AgentChangesList`（一覧と、それを取った範囲を組で持つ）と、範囲の一覧が取れなかったときの `{ kind: 'scope-unavailable'; scope; reason }`（セクションに理由を出す）
- 選んでいる範囲 `scope`（state と ref。既定 `{ kind: 'all' }`）と `selectScope(scope)` を足す。`selectScope` は `list` を null にして `refresh()` を呼ぶ
- `refresh` は今の範囲を渡し、結果は「要求の番号が最新」かつ「結果の範囲が今の範囲と同じ」ときだけ反映する（L-037・L-040）
- 範囲を `all` に戻す契機: フォルダの切り替え・`確認を終える`・新しい記録（`startedAt` が変わった）・届いた `runs` に選んでいる `runId` が無い・`scope-unavailable` の `run-missing`。最後の 2 つは取り直しと、セクションの常設の aria-live への `実行 N の記録は古くなったため消えました。すべて（累積）を表示します` の読み上げを伴う（N は消える前の写しの番号）
- `begin(trigger)`: 引数を必須にする。記録がある間の `send` の `begin` が例外になったら写しを変えない（記録はあるため。今は例外で `unavailable` にしている。区切りが取れなかったことは main の `runs` で分かる）
- `useAgentChangesRecording`: `beginAndRefresh` を `beginForSendAndRefresh`（`send`。`useAppState` の `beforeAgentSend`）と `beginManuallyAndRefresh`（`manual`。セクションの `いまから記録する`・`もう一度試す`）の 2 つにする。どちらも参照を描画をまたいで変えない
- 実行中にアプリで保存したパス（`savedPaths`）は今どおり記録ごと（`startedAt` が同じ間は保つ。実行を足しても捨てない）

### セクション（`AgentChangesSection`）

- 範囲の選択: 記録中で `runs` が 1 件以上のとき、見出しの下に `<label for>` の `表示` と `<select>` を出す。項目の文字:
  - `すべて（累積・HH:MM から）`
  - 選べる最後の実行: `実行 N（HH:MM から）`
  - 選べる途中の実行: `実行 N（HH:MM〜HH:MM）`
  - 開始を記録できなかった実行（`disabled`）: `実行 N（HH:MM・開始の状態を記録できませんでした: <理由>）`（理由は今の `unavailable` の文言の短い形）
  - 終わりを記録できなかった実行（`disabled`）: `実行 N（HH:MM〜・次の実行の開始を記録できなかったため比べられません）`
  - 戻す操作の実行中は `<select>` を `disabled` にし、今の理由（`aria-describedby` の `reasonId`）を結ぶ
- 見出し: 累積は今どおり。実行の範囲は `エージェントの変更 (N)（実行 3・HH:MM から）`（途中の実行は `HH:MM〜HH:MM`）
- 空の文言: 実行の範囲は `この実行では、変わったファイルはありません`
- HEAD の帯: 実行の範囲は `この実行の間に HEAD が変わりました（コミット・ブランチの切り替えなど）`
- 範囲の一覧が取れない（`scope-unavailable` の `start-not-recorded`・`end-not-recorded`）: 一覧の代わりに選択の項目と同じ理由を出す（ふつうは選べないため、届くのは写しが古いときだけ）。このとき agent の diff タブは閉じない（一覧から消えたかが分からない）が、アクティブな agent の diff タブは取り直し、前の範囲の内容を出し続けない（取り直すと diff タブにも取れない理由が出る。ローカルレビュー第 14 周の指摘で追加）。取れないまま静かな取り直しが続くときは、一覧が出ているときと同じく、写しが同じなら置き換えず `quietRefreshCount` を進め、diff も静かに取り直す（`読み込み中...` に変えない。第 15 周の指摘で追加）
- 戻すボタン: 実行の範囲（今の範囲、または表示中の一覧の範囲が `all` でない）では、行の `↶` と `すべて戻す` を `disabled` にし、`AGENT_CHANGES_REVERT_DISABLED_RUN_SCOPE` の理由を今の理由の領域に出す。理由の優先順位は、今の理由（Git の操作の実行中・取得中など）の後。`確認を終える`・`更新` は範囲に関わらず押せる
- `useAgentChangesRevert` の処理の側の守り: 表示中の一覧の範囲が `all` でなければ、確認を出さずに何もしない（L-058）。IPC には表示中の一覧の範囲を渡す（`all` のときだけ呼ばれる）

### diff タブ

- `useDiffOperations` は agent の diff の内容と一緒に、取った範囲（`agentDiffScope`）を持つ。`useCombinedEditorTabs` のラベルは、内容の範囲（diff を取った範囲。セクションで今選んでいる範囲ではない）が実行のとき `<path> (エージェントの変更・実行 N)` で、N はその範囲の `runId` の実行の番号（写しの `runs` から引く）。内容がまだ無い間は、今どおり `<path> (エージェントの変更)` にする（範囲を切り替えた直後に、前の範囲の内容へ新しい範囲の番号を付けない）
- `fetchDiffForTab` の文脈に `agentScope` を足し、`agent` のタブは `getAgentChangeDiff(path, agentScope)` で取る
- `AgentDiffActions.canRevertHunk` は、今の条件（`canRevertAgentHunk`）に「内容の範囲が `all`」を足す。`onRevertHunk` は内容の範囲を `revertAgentChangeHunk` に渡す
- 範囲を変えたときは、届いた一覧に無いパスの diff タブを閉じ、アクティブな diff タブを取り直す（今の `findAgentDiffTabsToClose`・`refreshDiff` の流れ。一覧が null の間は閉じない）

### 自動の取り直し（新しい hook `useAgentChangesAutoRefresh`）

- 入力: `isRecording`（`view.kind === 'recording'`）・`refresh`・`tabs`（`AgentNotificationTab` の形の一覧）・`activities`
- 活動の出来事: effect で `advanceAgentNotifications(settledRef.current, tabs, activities)` を呼び、`settled` を覚え直し、`events` が 1 件以上なら予約する（通知の `useAgentNotifications` と同じ純粋な関数を使い、別の判定を作らない。通知の設定・方式には依らない。閉じる途中のタブは出来事にならない）
- フォーカスの復帰: `window` の `focus` と、`document` の `visibilitychange` で `visibilityState === 'visible'` のときに予約する（`useExternalFileChanges` と同じ購読の形）
- 予約（`schedule`）: 記録中でなければ何もしない。待ちのタイマー（最後の予約から `AUTO_REFRESH_WAIT_MS = 300`）を張り直し、上限のタイマー（最初の未処理の予約から `AUTO_REFRESH_MAX_WAIT_MS = 1000`）は無ければ張る。どちらかが鳴ったら両方を取り消して走らせる
- 走らせる（`run`）: 自動の取り直しの実行中なら「もう 1 回」の印だけ立てる。そうでなければ `refresh({ announce: false, quiet: true })` を待ち、終わったときに印があれば 1 回だけ走らせ直す（そのときも記録中でなければ走らせない）
- 静かな取り直し（`quiet`。ローカルレビュー第 4 周の指摘 1・2 で追加）: 取り直しの間も前の一覧を出したままにし、`isLoading` を立てない（`↶`・`すべて戻す`・ハンクの戻すを押せなくしない。押せなくなると、そこにあったキーボードのフォーカスが body に落ちる）。結果が届いたら、一覧の中身（記録の始点・実行の一覧・行の並び・各行の状態と `notRecorded`・件数・打ち切り・HEAD の帯）が前の写しと同じなら写しを置き換えない（参照を保つ。`isSameAgentChangesView`）。一覧が変わったときだけ置き換え、今までどおり消えたパスの diff タブを閉じる。古い結果の破棄（要求の番号・範囲）は手動の取り直しと同じで、静かな取り直しが手動の取り直しを追い越したときは、静かな方の完了で `isLoading` を下ろす。古い一覧のまま戻す操作を押しても、main の expected の照合と記録の照合が防ぐ。一覧の取得に失敗したとき（ローカルレビュー第 9 周の指摘で追加）は、エラー（`listError`）を出さずに前の一覧を残す（`listError` は戻す操作を押せなくし、フォーカスを body に落とすため）。前から出ているエラーは消さず、次の取り直しの成功で消す。ただし、まだ答えていない手動の取り直しを静かな取り直しが追い越して失敗したとき（ローカルレビュー第 11 周の指摘で追加）は、押した `更新` の答えとして手動と同じくエラーを出す
- 静かな diff の取り直し（ローカルレビュー第 4 周の追加の指摘）: 静かな取り直しが一覧を反映するたびに（一覧が同じで写しを置き換えなかったときも）、`useAgentChanges` は `quietRefreshCount` を進める（失敗・捨てた結果・手動の取り直しでは進めない）。`useAgentChangesWiring` は写しと `quietRefreshCount` を 1 つの effect で見て、静かな完了を含む変化なら、アクティブな agent の diff タブを `refreshDiff({ quiet: true })` で 1 回だけ取り直す（行の状態が `M` のまま同じファイルに続きを書いた変更も、完了・許可待ちの時点の最新の diff として出す）。`useDiffOperations` は、静かな取り直しでは同じタブの内容を出したまま取り（`読み込み中...` にしない）、届いた内容が同じなら置き換えない（文字列が同じなので描画を省き、範囲も同じなら参照を保つ。DiffView を作り直さず、スクロールとフォーカスを保つ）。違うときだけ置き換える（そのときはスクロールが先頭に戻ってよい）。古い結果の破棄はこれまでの diff の取り直しと同じ（タブの切り替え・閉じる・次の取得で前の取得を捨てる。範囲は取得の時点の範囲を内容と組で持つ）。タブを切り替えた直後・表示中の内容を取った範囲と今の範囲が違うとき（範囲を変えた直後に静かな取り直しが手動の取り直しを追い越した。ローカルレビュー第 19 周の指摘で追加）・同じ描画で手動の取り直し（ハンクの操作の後の取り直しを含む）も頼まれたときは、手動と同じく内容を消してから取る。取得に失敗したら、手動と同じく内容と範囲を消してエラーを出す（古い内容からハンクを戻させない）。エラーを出している同じタブの静かな取り直しは、届くまでエラーを出したままにし（`読み込み中...` に変えない）、同じ文言の失敗が続いたら前のエラーを保つ。成功したら内容に置き換える（ローカルレビュー第 16 周の指摘で追加。当初は失敗の後の静かな取り直しを手動と同じく扱い、前のエラーを消してから取っていた）。手動の契機（`更新`・`変更を確認`・git status の更新・セッションの終了）は今までどおり（一覧が変われば内容を消して取り直す）
- 記録中でなくなった・フォルダが変わった・アンマウント: タイマーを取り消し、印を下ろす（世代で古い完了を区別する）
- 既存の契機（`変更を確認`・`更新`・git status の更新・セッションの終了）はこの hook を通さない

## エラー処理

| 状況                                                | 扱い                                                                                                                                                 |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 区切りの取得の失敗（上限・打ち切り・git）           | 送信は続ける。実行は `start-not-recorded` として足し、その実行と 1 つ前の実行を選べなくする（項目に理由）                                            |
| 区切りの写しの元が無い                              | `git-failed` として扱う（空から始めない）                                                                                                            |
| 区切りの取得中の `確認を終える`・フォルダの切り替え | 世代で取り消し、一時ディレクトリを消す。実行は足さない                                                                                               |
| 範囲の実行が消えた（`run-missing`）                 | 範囲を累積に戻して取り直し、読み上げる                                                                                                               |

### 結合（実 git。既存の流儀〈`isolatedGitEnv`〉）

- 区切りを 2 つ取り、途中の実行・最後の実行・累積の一覧が、それぞれの範囲の変更だけになる。同じファイルを実行 1 と実行 2 で変えたとき、実行 2 の diff の文脈に実行 1 の行が入る

- `gc --prune=now` の後に途中の実行の一覧が gc の文言で失敗する
- 戻す系の IPC に実行の範囲を渡すと、作業ツリーが変わらない（変異: 範囲の検査を外すとテストが落ちる）

## 実機テスト仕様書の方針

`docs/manual-test-spec.md` の「## エージェントの変更の確認」の末尾に 2 つの `###` を足す。前提は今の節の前提（テスト用のリポジトリ・`claude` の起動）を使う。

`### 実行ごとの記録`（AGC-039〜）:

- 2 回続けて `実行` で送る（実行 1 で `a.txt`、実行 2 で `b.txt` と `a.txt` の別の行を変える）→ 一覧の上に `表示` の選択が出て、項目が `すべて（累積…）`・`実行 2（…から）`・`実行 1（…〜…）` の順。`実行 1` を選ぶと `a.txt` だけ、`実行 2` を選ぶと `a.txt`・`b.txt` が出て、`実行 2` の `a.txt` の diff には実行 2 の行だけが変更として出る。`すべて` に戻すと両方の変更が出る
- `実行 1` を選んだ状態で → 行の `↶`・`すべて戻す` が押せず、一覧の上に `実行ごとの表示では戻せません。「すべて（累積）」を選ぶと戻せます` が出る（VoiceOver でボタンを選ぶと理由が読まれる）。`a.txt` の diff タブのラベルが `a.txt (エージェントの変更・実行 1)` で、ハンクの `このハンクを実行前に戻す` が無い。`確認を終える`・`更新` は押せる
- `b.txt` の diff タブを開いた状態で `実行 1` を選ぶ → `b.txt` のタブが閉じる。`a.txt` の diff タブを開いたまま範囲を変えると、内容がその範囲の差分に変わる
- `確認を終える` の後、`いまから記録する` を押してから端末で `echo x >> c.txt` を実行し、`実行` で 1 回送る → 項目は `すべて` と `実行 1` で、`c.txt` は `すべて` にだけ出る
- `実行` で 11 回送る（指示は「`n.txt` に 1 行足して」など短いもの）→ 項目は `実行 11`〜`実行 2` の 10 件で、`実行 1` が消える。`実行 1` を選んだまま 11 回目を送ると、範囲が `すべて` に戻り、`実行 1 の記録は古くなったため消えました。すべて（累積）を表示します` が読み上げられる。`すべて` には実行 1 の変更も出る
- 記録がある状態で、端末で `mkdir many && for i in $(seq 1 5001); do : > many/$i.txt; done` を実行してから `実行` で送る → 送信はされる。項目の最後の実行が選べず `開始の状態を記録できませんでした: 未追跡のファイルが多すぎます` を含み、1 つ前の実行も選べず `次の実行の開始を記録できなかったため比べられません` を含む。端末で `rm -rf many` を実行してからもう 1 回送ると、新しい実行は選べる
- 実行 2 でエージェントにコミットさせる → `実行 2` を選ぶと `この実行の間に HEAD が変わりました（コミット・ブランチの切り替えなど）` が出て、`実行 1` では出ない
- `確認を終える` の後に `実行` で送る → 選択の項目は `すべて` と `実行 1` だけ（番号が 1 から振り直される）
- 実行の後に端末で `git gc --prune=now` を実行し、途中の実行を選ぶ → `実行前の内容が見つかりません（git gc などで消えた可能性があります）` が出る
- ウィンドウ幅 500・640・1280px で、選択とその項目の文字が切れずに読める（長い項目は選択の中で末尾が省略され、開くと全文が見える）。VoiceOver で選択を選ぶと `表示` と選んでいる項目、選べない項目は「淡色」として読まれる

`### 一覧の自動の取り直し`（続きの番号）:

- 記録がある状態でソース管理パネルを開いたまま、`実行` で「`d.txt` を作って」を送り、何も押さずに作業の終わりを待つ → 完了の通知（または読み上げ）の後、1 秒ほどで一覧に `A d.txt` が出る。件数は読み上げられない（完了の読み上げだけ）
- ファイルを書き換えた後に許可を求める指示（「`e.txt` を作ってから `ls` を実行して」で、`ls` の許可を求めさせる）を送り、許可を待っている間に一覧を見る → `A e.txt` が出ている（許可を求めた時点で取り直す）
- 記録がある状態で、アプリの外の端末で `echo y >> c.txt` を実行してからアプリに戻る（`Cmd+Tab`・ウィンドウのクリック）→ `更新` を押さずに一覧に `c.txt` が出る。ウィンドウを最小化して戻したときも同じ
- 記録が無い状態で、アプリの外へ移ってから戻る → セクションに `更新中…` が出ない（取り直さない）
- `実行 1` を選んだ状態でアプリの外へ移って戻る → 範囲は `実行 1` のまま
- ソース管理の「変更」の一覧は、フォーカスの復帰では変わらない（端末で変えたファイルは、ソース管理の `更新` を押すまで「変更」に出ない）
- 取り直しの間もセクションに `更新中…` が出ず、`↶`・`すべて戻す` は淡色にならない。`↶` にキーボードのフォーカスを置いたまま戻っても、フォーカスは `↶` に残る（AGC-061）
- agent の diff タブを途中までスクロールし、ハンクの `このハンクを実行前に戻す` にフォーカスを置いてから、一覧を変えずにアプリの外へ移って戻る → diff は `読み込み中...` にならず、スクロールの位置とフォーカスはそのまま（AGC-059）。一覧が変わったら diff タブを取り直す（AGC-060）。完了・許可待ちの後、同じファイルの続きの変更（行の状態は `M` のまま）が開いている diff に `読み込み中...` を挟まずに反映される（スクロールは中身が変わったときだけ先頭に戻る。AGC-062）

既存の項目への影響（パターン 160）:

- AGC-037: 期待結果に「続けて `Cmd+Tab` でアプリへ戻っても（一覧の自動の取り直しが走る）、フォーカスは diff タブのタブへ飛ばない」を足す（ID は変えない）
- AGC-002・AGC-008・AGC-020・AGC-028 など `更新` を押す手順は、自動の取り直しの後に押しても結果が同じため変えない
- ソース管理（GIT・DSC）の項目は、git status を自動で取り直さないため影響しない

## 既知の制約（ROADMAP・実機テスト仕様書に反映する）

- 実行の区切りは、アプリからエージェントへ送ったとき（一覧・変数のフォームの `実行`、履歴のエージェントのエントリの `再実行`。どれも `useAgentPromptSender.send` の送信の前の準備を通る）だけ取る。ターミナルへ直接打ち込んだ指示は区切りにならず、前の実行に含まれる
- 区切りは送信の手順（貼り付け・Enter）の前に取るため、その後の送信が失敗しても実行は 1 つ増える（変更の無い実行になりうる）。送信前の確認をキャンセルしたときは、準備の前に止まるため増えない
- 区切りの取得を送信の前に待つのは 10 秒まで（今の始点と同じ）。超えると、区切りが終わる前にエージェントが書いた変更はその実行の開始の記録に含まれ、その実行ではなく 1 つ前の実行の変更として出る（ローカルレビュー第 22 周で記述を訂正）
- 送るたびに区切りの取得の分だけ送信が遅れる（設計の時点では、変わったファイルが少なければ 0.1 秒未満と見込んでいた。実装の Task 1 の実測〈未確認事項 1〉では、このリポジトリの写しと追跡済み 10,000 件のリポジトリで約 190〜310 ミリ秒。未追跡のファイルがほぼ無い条件で、未追跡のファイルが多いと延びる）
- 区切りの未追跡のファイルの検査は、累積の始点と同じく利用者の index を基準にする（Task 1 のレビューで変更）。前の記録で追跡していた 5MB を超えるファイルを記録の後に利用者が `git rm --cached` すると、区切りではそのファイルを除外し、その区切りで終わる実行の一覧では中身を記録していない `M` の行になる（累積の始点を利用者の index から取るときと同じ扱い）
- 実行は新しい方から 10 件まで。それより古い実行は選べない（累積には残る）
- 記録はウィンドウごとに 1 つで、エージェントのタブごとには分けない。タブ 1 とタブ 2 に交互に送ると、実行はタブをまたいで送った順に並ぶ（選択の項目にタブ名は出さない）。複数のタブのエージェントが並行して動くと、実行 N の範囲に別のタブのエージェントの変更も混ざる
- 途中の実行で、両端で ignore されていた（記録の時点に ignore 済みだった）ファイル・中身を記録していない入れ子のリポジトリは、中身が変わっても一覧に出ない
- 区切りを取れなかった実行と、その 1 つ前の実行は選べない。エージェントが ignore されていない未追跡のファイルを 5,000 件を超えて作る（`node_modules` など）と、それを消すか ignore するまで以後の区切りも取れない（数えるのは利用者の index から見た未追跡のファイル全体で、実行の前からあったものと前の記録に入ったものも含む）
- 実行ごとの表示は見るだけで、戻す操作は累積の表示でだけ使える。任意の 2 つの実行の比較はできない
- 途中の実行の一覧は、新しいフォルダを 1 行にまとめず、ファイルごとの行になる（500 行で打ち切る）
- 実行の中の利用者の編集（アプリの外を含む）は、その実行の変更として出る。`あなたの保存を含む` の印は累積の表示でだけ出る
- 区切りの記録のために、変わったファイルの blob と tree を利用者のリポジトリの object の DB に書く（到達できない object として既定の gc で 2 週間の後に消える）。`git gc --prune=now` などの後は、途中の実行が表示できない
- 自動の取り直しは、活動の判定（画面の読み取り）が完了・許可待ちと判定したときと、ウィンドウのフォーカスの復帰のときだけ。判定が外れたとき（判定できない画面・描画の間にまとまった変化）は取り直さない。git status（ソース管理の一覧）は自動では取り直さない
- フォーカスの復帰の自動の取り直しは、エージェントの作業中でも走る（書きかけの状態の一覧が出ることがある）

## 未確認事項（実装の最初に確かめる）

1. 区切りの取得（写し・`add -A`・`ls-files --ignored`・`write-tree`）の時間。このリポジトリの写しと、2026-10-06 の確認の結果 6 の大きいリポジトリで、写しの元を直前の記録にした場合と `.git/index` にした場合
2. 写しの元を直前の記録のインデックスにしたとき、`.git/index` から作った場合と同じ tree になるか（利用者が記録の後に `git rm --cached` したパス・intent-to-add のエントリ・コンフリクト中のエントリ）。違う場合は既知の制約に足すか、写しの元を `.git/index` に戻す

4. 実物の `claude` で、完了・許可待ちの活動の判定から自動の取り直しまでの時間（活動の判定のデバウンス + 300ms〜1,000ms）

5. **renderer の写しと範囲**（`useAgentChanges`・`useAgentChangesRecording`・`agentChangesApi`）
6. **セクションの範囲の選択・実行の範囲の表示・戻すの無効・diff タブの範囲**
7. **自動の取り直し**（`useAgentChangesAutoRefresh`・wiring・`useAppState` の配線）と結合テスト

## 反映した知見（dev-flow-kit の review-lessons.md）

- L-002: 終わりの区切りが無い実行を「今まで」に読み替えず選べなくする。写しの元が無いときに空から始めない（「決めたこと」・「`takeBaselineSnapshot` の変更」）
- L-003: 一番古い区切りを消すのは、新しい実行の結果が決まって一覧に足した後（「依頼の流れ」4-6）
- L-004: 消すのは自分が作った区切りの一時ディレクトリだけで、累積の始点と共有する実行 1 の記録は消さない（「決めたこと」10 件）
- L-010: `clear` はすべての区切りの削除を、1 つが失敗しても試す（「依頼の流れ」）
- L-019: renderer が渡すのは範囲の列挙と `runId` だけで、記録のインデックス・tree は main が決める（「IPC の範囲の引数」）
- L-034: `runId` は git の引数に入れず、パスは `:(literal)` と `--` で渡す（「範囲ごとの一覧と diff」）
- L-037: `runId` を記録をまたいで重ならない値にし、一覧の結果を範囲と組で持って照合する（「実行の番号と ID」・`useAgentChanges`）
- L-039: 戻す操作の実行中は範囲を変えられない（「範囲を変えたとき」）
- L-040: 範囲の違う古い一覧の結果を、要求の番号と範囲で捨てる（`useAgentChanges`）
- L-044: `trigger`・`scope` を必須にし、省略・未知の値を既定の解釈に流さず例外にする（「入力の検証」）
- L-052: 区切りの取得は git のコマンドごとの 10 秒の打ち切りと、送信の前の 10 秒の待ちの上限を引き継ぐ（「`takeBaselineSnapshot` の変更」・既知の制約）
- L-057: 選べない実行の理由を項目の文字に、戻すの無効の理由を見える文字で出して `aria-describedby` で結ぶ（「セクション」）
- L-058: 戻すボタンを `disabled` にするだけでなく、hook と main でも累積以外を拒む（「戻す系の IPC」・「新しい状態と既存の入口」）

- L-061: 「実行の範囲（読み取り専用）」に対し、作業ツリーを書き換える入口を列挙して扱いを表にする（「新しい状態と既存の入口」）
