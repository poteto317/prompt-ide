# エージェントへ送るプロンプトにファイルの参照を添える 設計書

- 日付: 2026-10-10
- ROADMAP の項目: 「エージェント実行の支援（MVP の次）」→「開いているファイル・選択範囲・ファイルパスを参照として添える（`@` 参照など。従来のファイル内容の添付に代わる手段）」
- 前提の設計書: `2026-10-04-agent-terminal-mvp-design.md`（C2: エージェント CLI 方式ではファイル内容を添付しない）、`2026-10-10-agent-send-confirm-design.md`（送信前の確認）

## 目的

エージェント CLI 方式では、従来の方式のような「開いているファイルの内容の自動の添付」をしていない（`claude` が自分で読むため）。
その代わりに、開いているファイル・エディタの選択範囲・エクスプローラで選んだファイルを、`claude` の `@` 参照（`@相対パス`）としてプロンプトの末尾に添えられるようにする。
`claude` に「どのファイルのどこを見てほしいか」を、パスを手で打たずに伝えられるようにする。

## 決めたこと（利用者の確認済み）

| 項目 | 決定 |
| --- | --- |
| 添え方 | 実行ごとに選ぶチップ。プロンプトパネルに「開いているファイル」「選択範囲」のチップを出し、オンにしたものを `実行` のときに本文へ足す。エクスプローラの右クリック「参照として添える」で任意のファイルも足せる |
| 選択範囲 | パスと行の範囲だけを渡す（`@src/a.ts#L10-20`）。中身は `claude` が読む。未保存の編集は `claude` に見えないため、未保存なら注意を出す |
| 位置 | 本文の末尾に、空行を挟んでまとめる |

## 範囲

含めるもの:

- 参照の文字列を組み立てる純粋な関数（相対パス・行の範囲・末尾への連結）
- プロンプトパネルの参照のチップ（開いているファイル・選択範囲・エクスプローラから足したファイル）
- エディタの選択範囲の追跡（行の範囲とそのファイル）
- エクスプローラの右クリックの「参照として添える」
- `実行` のときに参照を本文へ足す（送信前の確認には足した後の全文が出る）

含めないもの:

- 選択したテキストそのものを本文に貼ること
- `{{file}}` のような変数での位置の指定
- ターミナルの入力欄へ参照だけを直接入れる操作
- 従来の方式（API・非対話 CLI）での参照（従来どおり開いているファイルの内容を添付する）
- ドラッグ＆ドロップでの追加

## 参照の書式

本文の後に、空行を 1 つ挟んで次のように足す（参照が 1 つも無ければ何も足さない）。

```
<本文>

参照:
- @src/app.ts
- @src/lib/util.ts#L10-20
- @docs/notes.md
```

- パスは開いているフォルダ（`claude` の作業フォルダと同じ）からの相対パスで、区切りは `/` にそろえる（Windows でも）。
- 選択範囲は、パスの直後に空白を入れずに `#L10-20`、1 行なら `#L10` を付ける（Claude Code の IDE 連携が選択範囲の参照に使う書式に合わせる。全角の注記を続けると、`claude` が空白までをパスとみなして読み違えるため）。選択の終わりが行頭（列 1）で、開始行より後なら、その行は含めない（行を丸ごと選んだときの見た目に合わせる）。
- 本文は bracketed paste で貼り付けて送るため、貼り付けた文章の中の `@` 参照を `claude` が展開するかは実機で確かめる（自動テストでは確かめられない。実機テスト仕様書の最初の項目にする）。展開されない場合でも、パスと行の範囲は文章として `claude` に伝わる。また、本文は `@パス` で終わるため、送信の Enter が `claude` の `@` の候補の確定に取られないか（Enter 1 回で送られるか）も実機で確かめる（同じ項目）。取られる場合は、末尾の参照の後に区切りを入れるなどの対策を別に検討する。
- 同じパスが複数回出るときは、1 回にまとめる（同じファイルかは絶対パスを `toComparablePath` で正規化したキーで比べ、表記は先に出たものを使う。Windows で大文字小文字だけが違う表記も同じファイルとしてまとめる）。ただし、行の範囲が付いたもの（選択範囲）と付いていないもの（ファイル全体）は別の参照として両方出す（ファイル全体を先に）。
- 並びは、開いているファイル → 選択範囲 → エクスプローラから足した順。
- フォルダの外のファイル・パスを持たないもの（差分のタブなど）は参照にできない（チップを出さない・押せない）。

## プロンプトパネルのチップ

- エージェント CLI 方式で、フォルダを開いているときだけ、プロンプトの一覧の上に「参照」の行を出す。従来の方式では出さない。
- チップ（`button`・`aria-pressed`）:
  - **開いているファイル**: アクティブなタブが実ファイルのとき、`@src/app.ts` のように相対パスを出す。押すとオン・オフ。アクティブなタブが無い・差分のタブ・フォルダの外なら押せず、理由を `title` と `aria-describedby` で出す（`開いているファイルがありません`・`差分のタブは参照にできません`・`フォルダの外のファイルは参照にできません`）。
  - **選択範囲**: アクティブなエディタに空でない選択があるとき、`@src/app.ts#L10-20` のように出す。押すとオン・オフ。選択が無ければ押せない（`エディタで範囲を選ぶと添えられます`）。差分のタブでは、差分の表示で範囲を選んでも添えられないため、開いているファイルのチップと同じく押せず `差分のタブは参照にできません` を出す。
  - **エクスプローラから足したファイル**: 足したファイルごとに `@docs/notes.md ×` を出す。`×`（`aria-label="@docs/notes.md を参照から外す"`）で外す。
- 開いているファイル・選択範囲のチップは、アクティブなタブ・選択が変わると中身（パス・行の範囲）が追従する。オン・オフの状態は保つ（タブを切り替えても「開いているファイルを添える」はオンのまま）。
- 未保存の注意: オンにした開いているファイル・選択範囲のファイル、エクスプローラから足したファイル（アクティブでないタブで開いているものも含む）に未保存の変更があるとき、チップに `未保存` の印を付け（`@src/app.ts 未保存`・`@docs/notes.md 未保存 ×`。印は名前の後ろに空白を挟んで出し、開いているファイル・選択範囲のチップではボタンの名前に含める）、送信前の確認のダイアログに `未保存の変更があるファイルは、保存するまで claude に見えません: src/app.ts` を出す（送信は止めない）。どの入口から添えても同じく知らせる。一覧では同じファイルを 1 回にまとめる（同じファイルかは、相対パスの文字列ではなく絶対パスを `toComparablePath` で正規化したキーで比べる。Windows の大文字小文字・区切りの違いを吸収する）。未保存の判定は、そのファイルのタブの `content` と保存した内容の比較（既存のタブの未保存の印と同じ規則。タブが無ければ未保存ではない）。ダイアログに出す一覧は、`実行` を押した時点の写しとして確認の状態に持たせる（開いている間に保存しても消さない）。送信前の確認がオフのときは、チップの印だけで知らせる。
- 未保存の一覧と、送れたときの知らせを運ぶため、`sendToAgent` の第 2 引数を `{ promptId, unsavedPaths, onSent }` のオプションにする（`usePromptRunner` の `Deps.sendToAgent`・`useAgentWorkspace.sendToAgent`・`useAgentSendConfirm.request`・`PendingAgentSend`・`AgentSendConfirmDialogState.pending` の型を広げる）。`onSent` は送信の結果が `sent` のときだけ呼ぶ（確認がオンなら確認から送れたとき、オフならすぐ送って送れたとき）。確認がキャンセル・フォルダの切り替えなどで閉じたときは呼ばない。
- エクスプローラから足したファイルは、送れた（`sent`）ら外す。外すのは `実行` を押した時点に本文へ入れたものだけ（その時点の写しを `onSent` の中で使う。確認を開いている間に足したものは残す）。キャンセル・送信の失敗では外さない。開いているファイル・選択範囲のオン・オフは送った後も保つ。
- フォルダを切り替えたとき・従来の方式へ切り替えたときは、エクスプローラから足したファイルを外し、開いているファイル・選択範囲をオフに戻す。
- タッチで押せる大きさ（32px 以上）。ダークテーマ。

## エクスプローラ

- ファイルの右クリックのメニューに `参照として添える` を足す（エージェント CLI 方式のときだけ。フォルダには出さない）。押すと、そのファイルをエクスプローラから足したファイルの末尾に加える（すでにあれば一覧は変えず、`@docs/notes.md はすでに参照にあります` を読み上げる。プロンプトパネルが隠れている間も結果が伝わるように）。
- 加えたら、プロンプトパネルの参照の行に出る。`参照に @docs/notes.md を足しました` を読み上げる。エクスプローラを開いている間はプロンプトパネルが隠れるため、読み上げは App の常設の読み上げの領域に出す（通知の機能の `AgentAnnouncer` と同じ形の常設の `aria-live` を参照用に 1 つ足す）。
- メニューの項目は、`buildMenuItems` の `actions` に `onAddReference` があるときだけ出す（エージェント CLI 方式でないときは渡さない）。

## 送る流れ

- `usePromptRunner.runPrompt` のエージェント CLI 方式の分岐で、変数を差し込んだ後の本文に参照を足してから `sendToAgent` へ渡す（従来の方式の分岐は変えない）。
- 参照を足した後の全文が、送信前の確認のダイアログに出る（文字数・長さの上限の判定も足した後の全文で行う）。
- 参照は本文の後に足すので、本文の先頭が `!` かどうかの判定は変わらない。

## 構成

- `src/renderer/src/lib/agentReferences.ts`（新規）: 純粋な関数。
  - `toWorkspaceRelativePath(folderPath, filePath): string | null`（フォルダの外なら `null`。区切りは `/`）
  - `toLineSpan(selection): LineSpan`（選択の行の範囲。終わりが列 1 の扱いを含む）・`formatLineSpan(span): string`（`#L10-20`・`#L10`）
  - `buildAgentReferenceList(input): AgentReference[]`（並び・重複のまとめ）
  - `appendAgentReferences(text, references): string`（末尾への連結。空なら本文のまま）
- `src/renderer/src/hooks/useEditorSelectionRange.ts`（新規）: アクティブなエディタの選択の行の範囲と、そのエディタのファイルのパスを追跡する。持つのはチップの表示を決める値（ファイルのパス・開始行・列 1 の補正の後の終わりの行）だけで、列は持たない（この hook は合成の根の `useAppState` にあるため、行の中で列だけが変わっても値を作り直さず、App 全体を描画し直さない）。`useAppState` で使い、`EditorPanel` に新しい prop（`onEditorMount(editor, filePath)`）を足して、既存の `onMount`（`attachEditor` を呼んでいる所）から呼ぶ。選択範囲のファイルは、マウントの時点の `openFile.path` を控える（エディタはファイルごとに付け替わる）。エディタが外れたら（差分のタブ・ファイルを閉じたときなど）選択を無しにする。外れたことは、取り付けたエディタの `onDidDispose` で知り、カーソルの変化の購読もそこで外す。
- `src/renderer/src/hooks/useAgentReferences.ts`（新規）: チップのオン・オフ、エクスプローラから足したファイル、フォルダの切り替え・送れたときの後始末を持ち、`実行` のときに使う参照の一覧を返す。
- `src/renderer/src/components/prompts/AgentReferenceChips.tsx`（新規）: チップの表示。
- `usePromptRunner.ts`・`useAppState.ts`・`App.tsx`・`EditorPanel.tsx`・`PromptsPanel.tsx`・`Sidebar.tsx`・`useAgentWorkspace.ts`・`useAgentSendConfirm.ts`: 配線（`sendToAgent` のオプション、選択範囲の取り付け、読み上げの領域）。
- `toWorkspaceRelativePath` は既存の `pathUtils`（`isPathInside`・区切りの扱い・Windows の大文字小文字）を使って作る。POSIX のファイル名に含まれる `\` は `/` に変えない。
- `explorerMenuItems.ts`・`ExplorerPanel.tsx`: 右クリックのメニュー。
- `AgentSendConfirmDialog.tsx`: 未保存の注意の表示。

## エラーと境界の扱い

- フォルダを開いていない・従来の方式: チップの行を出さず、参照を足さない。
- 開いているファイルが削除・改名された: アクティブなタブの状態に追従する（既存の扱いのまま）。エクスプローラから足したファイルが削除・改名されても、参照はそのまま残す（`claude` が見つけられなければ `claude` 側で伝える。既知の制約）。
- 参照を足した結果が長さの上限を超える: 送信前の確認の既存の「長すぎる」の理由で止まる。

## 既知の制約（ROADMAP・実機テスト仕様書に反映する）

- `@` 参照の解釈は `claude` に任せる（書式は `claude` の `@パス`・`#L開始-終了` に合わせた。パスに空白などを含むと `claude` が参照として解釈しないことがある。貼り付けた本文の中の `@` 参照が展開されるかは `claude` の版による）。
- 未保存の編集は `claude` に見えない（注意は出すが、送信は止めない）。
- エクスプローラから足したファイルが後で削除・改名されても、参照は自動では外れない。
- POSIX のルート（`/`）をフォルダとして開いたときは、相対パスを作れないため参照にできない。
- ファイル名に改行を含むと、参照の行が途中で折り返されて本文に入る。`#` を含むと、`claude` が行の範囲の区切りと読み違えることがある（送る全文は送信前の確認で確かめられる）

## テスト

- `agentReferences`: 相対パス（フォルダの直下・深い階層・フォルダの外・Windows の区切り・末尾の区切り）、行の範囲（1 行・複数行・終わりが列 1）、並びと重複のまとめ、末尾への連結（空・1 つ・複数）。
- `useEditorSelectionRange`: 選択の変化への追従、エディタの付け替え（タブの切り替え）、選択が空、行の中で列だけが変わっても値を作り直さない・描画し直さない。
- `useAgentReferences`: オン・オフ、追従、エクスプローラから足す（重複しない。重複のときはすでにあることを読み上げる）・外す、送れたら足したファイルだけ外す、フォルダの切り替えで戻す、未保存の判定（エクスプローラから足したファイルを含む。同じファイルは 1 回）、Windows の大文字小文字だけが違う同じファイルのまとめと「ファイル全体を先に」の並び。
- `usePromptRunner`: エージェント CLI 方式で参照を足した本文を `sendToAgent` に渡す、従来の方式では足さない。
- チップ: 表示・`aria-pressed`・押せない理由・`×`・未保存の印・32px。
- エクスプローラ: メニューの項目がエージェント CLI 方式のファイルだけに出る、押すと足される。
- 送信前の確認: 参照を足した全文と未保存の注意が出る。
