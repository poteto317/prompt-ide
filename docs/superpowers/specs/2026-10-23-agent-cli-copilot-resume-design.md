## 目的

段階 2b で、`copilot` のタブにもプロンプトを送れるようになった。ただし能力の表の `copilot` の `sessionResume` は `false` のままで、次の 3 つが使えない。

- ターミナルの帯の `前回の続きから`（`copilot では「前回の続きから」を使えません（設定で claude に戻すと使えます）`）
- 実行履歴の `このセッションで再開`（`copilot では「このセッションで再開」を使えません（設定で claude に戻すと使えます）`）
- `copilot` へ送ったプロンプトの実行履歴への記録（送り先の会話の ID を持たないため、黙って省いている）

この段階 3a では、`copilot` をアプリが決めた会話の ID で起動し、起動の記録・履歴に CLI の種類を持たせて、`copilot` のセッションも再開できるようにする。
`claude` を選んでいる間（既定）の挙動・文言・起動の記録のファイルは今までと同じにする。履歴のファイルは、`claude` のエントリにも種類の欄が 1 つ増える（古い版のアプリでも読める形。「履歴への CLI の種類」）。

## 起動の引数と環境変数（`agentCliLaunchSpecs.ts`）

### 引数

| 種類      | `new`                           | `resume`                      |
| --------- | ------------------------------- | ----------------------------- |
| `claude`  | `--session-id <ID>`（今のまま） | `--resume <ID>`（今のまま）   |
| `copilot` | `--session-id <ID>`             | `--resume=<ID>`（1 つの引数） |

- `copilot` の `buildCopilotArgs` は、会話の ID が無い（`null`）と投げる（`sessionResume` が `true` になるため。今の `claude` と同じ。L-044）。hooks の設定のファイルのパスが渡ったら今までどおり投げる（`changeAttribution` は `false` のまま）
- 再開は `--resume=<ID>` の 1 つの引数にする。`--resume` は値を省ける（`--resume[=<value>]`。省くと選択の画面）ので、`--resume <ID>` と 2 つに分けると ID が値として読まれない恐れがある。記録も `--resume=<ID>` で取った
- 再開に `--session-id` を使わない。記録の 6 のとおり、`copilot` 側にセッションが無いと黙って同じ ID の新しい会話になり、記録・履歴と実体がずれる。`--resume=<ID>` は無ければ終了コード 1 で分かる
- ID は常に main が振った・記録と照合した小文字の UUID v4 の完全な形（36 文字）だけを渡す。記録の 5 のとおり `--resume` は前方一致・名前でも照合し、UUID でない値は新しいセッションに落ちる（3'）ので、完全な UUID 以外を渡す経路を作らない（L-007・L-034）。`buildCopilotArgs` の先頭でも `isClaudeSessionId` で確かめ、合わなければ投げる（入り口の検証に加えた最後の守り。`claude` の `buildClaudeArgs` は今のまま）。投げる例外の文言は `spawn-failed` の detail として画面に出るので、渡された値を文言に入れない（L-017）
- 大文字を渡すと `copilot` は大文字の名前で保存する（記録の 5）。main の ID は `randomUUID()`（小文字）と、小文字だけを通す検証を通った値なので、大文字は渡らない

### 環境変数

- 起動の表に `extraEnv: Readonly<Record<string, string>>` を足す。`claude` は `{}`（今のまま）、`copilot` は `{ COPILOT_DISABLE_RESUME_AUTO_CD: '1' }`
- `resolveAgentLaunch` の `buildAgentEnv` で、取り除く一覧を適用した後に足す（利用者の環境に同じ名前があっても上書きする）。Windows は環境変数の名前の大文字小文字を区別しないので、足す前に大文字小文字だけ違う同じ名前を取り除く（`NO_PROXY` の扱いと同じ）
- `new` でも足す（`new` では効かない。記録の 4 の `07e` のとおり `--session-id` では移動しない）。起動の指定で環境を変えないほうが、起動の計画（`AgentLaunchPlan`）を起動の指定に依存させずに済むため

### `-C` ではなく環境変数にした理由

| 観点                         | `COPILOT_DISABLE_RESUME_AUTO_CD=1`                              | `-C <許可のフォルダ>`                                                                 |
| ---------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `copilot` の中の作業フォルダ | pty の `cwd`（許可のフォルダ）のまま（記録 `07b`）              | 指定したフォルダ（記録 `07c`）                                                        |
| `copilot` の保存先の書き換え | しない（`workspace.yaml` の `cwd` は元のまま）                  | する（`workspace.yaml` の `cwd` を書き換える）                                        |
| プロセスの作業ディレクトリ   | pty の `cwd` のまま                                             | `copilot` の native のプロセスの `cwd` も変わる（`07d`）                              |
| 段階 1 の方針                | 合う（作業ディレクトリは pty の `cwd` で決め、`-C` は使わない） | 方針を変える                                                                          |
| 引数にパスが入るか           | 入らない                                                        | 入る（main の値なので安全だが、`-` 始まりの解釈・Windows の引用を考える箇所が増える） |

利用者の `copilot` の保存先を書き換えず、段階 1 の方針も変えずに済むので、環境変数にした。

なお、起動の記録はフォルダごとで、再開の照合は許可のフォルダの記録だけを見る（「起動の流れ」）。そのため保存先が許可のフォルダと違うのは、会話の中で `copilot` の作業フォルダを変えたとき（`/cd` など）や、同じフォルダをシンボリックリンク越しに開いたときに限られる。そのような場合でも、許可のフォルダの外で `copilot` が動き出さないようにするための守り。

### 形

- `ipcHandlers.ts` は種類ごとに store を作り、`Record<AgentCliKind, AgentSessionRecordStore>` を starter に渡す（種類をキーにしたオブジェクトのリテラルで作る〈キーの欠けが型エラーになる〉。種類を足したときに記録の決め忘れを型エラーにする。L-060）

### 種類ごとのファイルにした理由（互換性）

| 案                                      | 古い版のアプリで読んだとき                                                                                           | 古い版のアプリが書いたとき                                                                                     |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |

今の `agent-sessions.json` の中身はすべて `claude` の起動のもの（段階 1・2 では `copilot` を記録しなかった）なので、移行は要らない。既存の ID・順序には触れない（L-456）。

## 起動の流れ（`agentSessionStarter.ts`）

今の流れ（`resolveLaunch` → 再開の可否 → hooks の準備 → 記録の読み込み → 取り消しの確かめ → 同期の区間で ID の選択・予約・spawn → 確定で記録）の順は変えない。変えるのは次の点。

1. **種類の照らし合わせ**（新規）: 再開の依頼で、能力の表の `sessionResume` の確かめ（今の `resume-unsupported`）の直後に、`request.launch.cliKind !== launch.plan.cliKind` なら `resume-cli-mismatch` で断る。hooks の準備より前（断るときに準備しない。今の `resume-unsupported` と同じ位置づけ）。起動に使う種類は `launch.plan.cliKind`（main が起動のたびに読んだ設定）で、依頼の種類は照らし合わせにだけ使う（L-018）
2. **記録の読み込みの待ち**: `records[launch.plan.cliKind].whenLoaded()` を待つ
3. **ID の選択**（`spawnSession`）: `selectClaudeSessionId(request.launch, folderKey, records[plan.cliKind], createClaudeSessionId)`。`copilot` も `sessionResume` が `true` になるので、`new` は振り、`resume` は `copilot` の記録と照合する（無ければ `unknown-session`）。`claude` の ID を `copilot` で再開する経路は無い（`claude` の ID は `copilot` の記録に無い）
4. **予約**: 今の共有の予約をそのまま使う
5. **記録**（`recordStarted`）: `records[cliKind].record(folderKey, claudeSessionId)`。再開の確定でも今と同じく先頭へ置き直す
6. **前回**（`lastSessionOf(ownerId, folderPath, cliKind)`）: 依頼の種類の記録の先頭を返す。戻り値は `{ cliKind, claudeSessionId }`（renderer が依頼と違う種類の結果を捨てられるように。L-037）

`recordStarted` の検査（`sessionResume` が `true` の種類は ID を必ず持つ、`false` の種類は持たない）は残す。今の表ではどちらの種類も `true` になるが、`false` の種類を足したときの守りになる。

### 知らない欄

段階 1 の設計書の「記録と履歴」は「知らない欄は保ったまま書き戻す（L-459）」と方針を書いた。段階 3a では、種類の値（知らない種類）は保つが、エントリや `agent` の知らない欄を保つ変更はしない（2026-10-23 に利用者が確かめて決めた）。

- 理由: 保存の経路は renderer が丸ごと送る履歴で、知らない欄を保つと renderer の任意の欄がファイルに残る。今のテスト（`historyUtils.test.ts` の「余分なプロパティを除去する」「agent の中の余分なキーを落とす」）はこの規則を固定している。段階 3a の版が書く欄はすべて知っている欄なので、今の利用には影響しない
- 新しい版で欄を足すときは、その版で段階 3a の版に戻したときに落ちることを既知の制約に書くか、欄を足す前の版で保つ規則を入れる（「次の段階の見通し」）

## 再開の入口（押せない理由）

### 前回の続きから（`getResumeLastDisabledReason`）

- `useAgentLastSession` は設定の種類（`appCliKind`）を受け取り、`getLastAgentSession(folderPath, appCliKind)` で取る。省略できない引数 `cliKind` を effect の依存に入れ（種類が変われば取り直す）、結果は「取りに行ったフォルダと種類」が今と同じときだけ使う（L-037・L-040）。結果の `cliKind` が依頼と違えば記録なしとして扱い、`console.error` に残す（起きない想定）
- 理由の順は今のまま（起動の理由 → 設定の種類の `sessionResume` → 取得中 → 記録なし → 同じ ID のタブ）。`copilot` も `sessionResume` が `true` になるので、`copilot` でも押せる
- 押したとき（`resumeLast`）は `{ kind: 'resume', claudeSessionId, cliKind: lastSession.cliKind }` で起動する
- `aria-label` は `agentResumeLastAriaLabel(commandName)` にして設定の種類のコマンド名を入れる。`claude` では今の文言と同じ（`前回の続きから（このフォルダで最後に起動した claude のセッションを再開）`）

### このセッションで再開（`getResumeEntryDisabledReason`）

上から順に、最初に当たったものを 1 つ出す。太字が足すもの。

1. 実行方式の読み込み中（今のまま）
2. エージェント CLI 方式でない（今のまま）
3. 設定の種類が再開に対応していない（今のまま。今の表では当たらない）
4. **エントリの種類が知らない種類**: `このアプリの版が知らないエージェント CLI（<種類>）のセッションのため、再開できません`
5. **エントリの種類と設定の種類が違う**: `<エントリのコマンド名> のセッションのため、<設定のコマンド名> では再開できません（設定の「使うエージェント CLI」で <エントリのコマンド名> に切り替えると再開できます）`
6. 記録したフォルダを開いていない（今のまま）
7. 起動を受け付けない間（今のまま）
8. 同じ ID のタブが起動中・実行中（今のまま）
9. タブが上限（今のまま）

種類の理由をフォルダの理由より前に置くのは、フォルダを開き直しても押せないため（設定を変えるまで押せない理由を先に出す）。押したとき（`onResumeEntry`）は、押した時点の理由を求め直し（L-058）、`resumeInNewTab(claudeSessionId, cliKind)` で起動する（`cliKind` はエントリの種類。4 と 5 を通った後なので設定の種類と同じ）。

### 履歴の `再実行`

変えない（`getHistoryRerunAvailability` はエントリの種類を見ない）。理由は「決めたこと（推奨案）」。

## 再開の失敗の見分け方と伝え方

- 種類ごとの表 `AGENT_RESUME_FAILURE_NOTES: Record<AgentCliKind, string | null>`（renderer の `lib/agentSessionMessages.ts`）を置く。`claude` は `null`（今のまま）、`copilot` は下の文言
- 判定は純粋な関数 `isAgentResumeFailure({ launchKind, exit, sawScreenActivity })`（`lib/agentSessionTabState.ts`）: `launchKind === 'resume'`・`exit.reason === 'exited'`・`exit.exitCode !== 0`（`null` も含む）・`sawScreenActivity === false`（起動の後に、そのタブの活動が一度も `unknown` 以外にならなかった）のときだけ真
- タブは起動の指定の種類（`new`・`resume`）と「活動を一度でも見たか」を起動ごとに持つ（起動し直すと戻す。控えの置き場は `lib/agentLaunchWatches.ts` の `createAgentLaunchWatches` で、持ち主は `useAgentSessions`）。活動は今の画面の判定（`screenActivity` が `true` の種類だけ）から取る
- 終了のとき、判定が真で、そのタブの種類の文言が `null` でなければ、その文言をタブの赤字に出す（今の「起動の直後に終了しました」より優先）。それ以外は今のまま
- 記録は消さない。終了コード 1 には `node` が見つからないなど別の原因もあり、それだけを根拠に記録を消すと、続けられるセッションの記録を失う（L-002・L-006）。そのため `前回の続きから` は、そのフォルダで次に新しく起動するまで同じセッションを指す（既知の制約）
- 文言は原因を言い切らず、ターミナルの表示（`copilot` の `Error: No session, task, or name matched …`）を見るよう案内する（L-017: `copilot` の出力を文言に写さない）

## 既知の制約（ROADMAP・実機テスト仕様書に反映する）

- `copilot` の再開の規則は GitHub Copilot CLI 1.0.87 の挙動（段階 3a の記録）に合わせている。`--session-id` は 1.0.51、保存先への自動の移動と `COPILOT_DISABLE_RESUME_AUTO_CD` は 1.0.52、`--resume=<値>` は 1.0.60 から。古い版や挙動が変わった版では、起動の直後に終わる・再開できない・新しい会話になることがある。アプリは `copilot` の版を確かめない
- `copilot` で何も送らずに閉じたセッション（`!` コマンドだけを送ったセッションは記録していない）は、`copilot` が会話を保存しないので再開できない。起動しただけで閉じるとそのセッションが「前回」になり、`前回の続きから` を押すと `copilot がセッションを再開できずに終了しました…` が出る。そのフォルダで新しく起動して何か送るまで「前回」は変わらない。履歴のエントリは送れたときだけ作られるので、履歴からは再開できる
- 再開の失敗の文言は、再開で起動して入力待ちなどの画面になる前に終了コード 0 以外で終わったときに出す。`node` が見つからないなど別の原因でも同じ文言になる（ターミナルの表示で確かめる）
- 再開できるのは設定と同じ種類のセッションだけ。`copilot` のエントリを再開するには設定を `copilot` に切り替える（切り替えると動いているタブはすべて止まる）。履歴の `再実行` は種類に関わらず選択中のタブへ送れる
- `copilot` の中の `/resume`・`/new`・`/clear` で会話が切り替わると、アプリが控えた ID（履歴・記録）とずれる。履歴と記録には起動したときの ID が残り、再開するとその会話が開く（`claude` の `/clear` と同じ）
- アプリの外（別の端末）で同じ `copilot` のセッションを開いているのは検知できない（アプリの中の二重の起動は拒む）。2 つの `copilot` で同じセッションを同時に開いたときの挙動は記録していない
- 再開でもフォルダの信頼の確認が出ることがある（その回だけ信頼した場合。帯は `確認待ち`）
- `copilot` の保存先（`workspace.yaml` の作業フォルダ）が許可のフォルダと違っても、`copilot` は許可のフォルダで再開する（`COPILOT_DISABLE_RESUME_AUTO_CD=1`）。`copilot` の保存先は書き換えない
- 古い版のアプリで段階 3a の履歴を保存すると、エントリの種類が落ち、段階 3a の版に戻したとき `copilot` のエントリは `claude` のエントリとして読まれる（`このセッションで再開` は種類が違うか、記録に無い理由で使えない）。古い版のアプリは `agent-sessions-copilot.json` を読まない
- 履歴の知らない種類のエントリ（新しい版で作ったもの）は、この版では `このセッションで再開` を使えない（`再実行` は使える）。エントリや送り先の知らない欄は保存のときに落ちる
- 履歴の `セッション:` の ID は、`copilot` のエントリでは `copilot --resume=<ID>` で手動で開ける ID（終了の画面の `Resume` の行と同じ）

## 実装の分割

選び方: 優先度 A のチェックリストを読み、起動の引数・永続化の形・互換性・入口の判定・失敗の伝え方・実機の手順に関係する項目の本文を読んだ（L-001・L-002・L-007・L-015・L-017・L-018・L-019・L-034・L-044・L-456・L-459・L-072）。優先度 B の「非同期・競合」「エラー処理」「データの互換性・永続化」「ドキュメント・仕様」は、上の A の項目と同じ型のもの（L-037・L-040・L-052・L-058・L-059・L-060・L-061・L-006・L-354）を当てはめた。

- L-001: 起動の記録は起動が確定した（started）ときだけ書き、書けなくても起動は成功として扱う（今の store の規則）。再開の失敗は終了の事実（終了コード・活動）から伝え、`started` を再開できた印にしない（「再開の失敗の見分け方と伝え方」）
- L-002・L-006: `copilot` の記録のファイルが読めないときは書かず、`claude` の記録と分ける（別の store）。終了コード 1 だけを根拠に記録を消さない（「起動の記録」・「再開の失敗の見分け方と伝え方」）
- L-007: `copilot --resume` は前方一致・名前でも照合するので、完全な小文字の UUID 以外を渡さない（「起動の引数と環境変数」）
- L-015: 履歴の `cliKind` は `isValidHistoryEntry` と `sanitizeHistoryEntry` の両方に足し、保存の往復で落ちないことをテストで固定する（「履歴への CLI の種類」）
- L-017: 新しい文言は固定の文で、`copilot` の出力や例外の文言を写さない。知らない種類の名前は形を検証した値だけを出す（「文言」・「エラー処理」）
- L-018: 起動の種類は main が読んだ設定の値で決め、依頼の種類は照らし合わせにだけ使う。照合した ID をそのまま引数にする（「起動の流れ」）
- L-019・L-034: renderer は列挙型の起動の指定だけを渡し、引数と環境変数は main の起動の表が組み立てる。ID は入り口で小文字の UUID v4 を検証し、記録と照合し、起動の表でも確かめる（「起動の引数と環境変数」・「IPC と型」）
- L-037・L-040: 「前回」の結果はフォルダと種類が今と同じときだけ使い、古い種類の結果を捨てる（「再開の入口」）
- L-044: 再開の依頼の種類・`getLastSession` の種類・履歴の形の不正な種類は、既定（`claude`）に流さずに拒む・捨てる。種類の無い古いエントリだけを `claude` として読む（「IPC と型」・「履歴への CLI の種類」）
- L-052: `copilot` の版を確かめる外部プロセスを足さない（「決めたこと（推奨案）」）
- L-058: `このセッションで再開`・`前回の続きから` は押した時点に同じ理由を求め直し、main も種類の照らし合わせ・記録の照合で同じ条件を守る（「再開の入口」）
- L-059: `copilot` の規則は実物の記録（`report.md`）で決め、引数と環境の経路は偽の実行ファイルと実物の node-pty の統合テストで確かめる。記録できなかった場面は既知の制約と実機の項目に回す（「テスト方針」・「既知の制約」）
- L-060: 種類ごとの記録の store・起動の表の `extraEnv`・再開の失敗の文言は `Record<AgentCliKind, …>` にし、起動の指定の `cliKind` と活動の受け渡しは省略できない形にして、配線のテストと変異の確認を入れる（「起動の記録」・「テスト方針」）
- L-061: 新しい状態（タブの起動の指定と活動を見たか・`copilot` のタブの ID）に対して入口を表にした（「新しい状態と既存の入口」）
- L-072: 実機の項目は記録のファイル・履歴のファイル・`~/.copilot` を消さず書き換えず（`ls` で見るだけ）、信頼の確認で覚えさせず、足したプロンプトと設定を節の最後で戻す（「実機テスト仕様書の方針と項目の下書き」）
- L-354: 実機テスト仕様書の下書きは、実装の後にコードの文言と照らし合わせて確定してから追記する
- L-456: 古い履歴・記録の ID・時刻・順序を作り直さず、欠けている `cliKind` だけを補う（「履歴への CLI の種類」・「起動の記録」）
- L-459: 起動の記録は、古い版の書き戻しで `copilot` の記録が消えないよう別のファイルにした。履歴は保存の欄名を保ち、知らない種類の値を保つ。知らない欄は保たない判断とその理由を書いた（「起動の記録」・「履歴への CLI の種類」の「知らない欄」）
